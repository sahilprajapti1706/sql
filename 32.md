## 32. Explain ROW_NUMBER().

### Answer

`ROW_NUMBER()` is a **window function** that assigns a **unique sequential number** to each row within the result.

The numbering is determined by the `ORDER BY` inside the `OVER()` clause.

### Basic Syntax

```sql
ROW_NUMBER() OVER (
    ORDER BY column
)
```

The numbering starts from **1**.

---

## Simple Example

Suppose we have:

| name  | salary |
| ----- | -----: |
| Sahil |  50000 |
| Rahul |  70000 |
| Priya |  60000 |
| Amit  |  40000 |

```sql
SELECT
    name,
    salary,
    ROW_NUMBER() OVER (
        ORDER BY salary DESC
    ) AS row_num
FROM employees;
```

Result:

| name  | salary | row_num |
| ----- | -----: | ------: |
| Rahul |  70000 |       1 |
| Priya |  60000 |       2 |
| Sahil |  50000 |       3 |
| Amit  |  40000 |       4 |

The rows are numbered according to salary from highest to lowest.

---

## `ROW_NUMBER()` with `PARTITION BY`

This is where `ROW_NUMBER()` becomes particularly useful.

`PARTITION BY` resets the numbering for each group.

Suppose we want to rank employees **within each department**:

```sql
SELECT
    name,
    department,
    salary,
    ROW_NUMBER() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS row_num
FROM employees;
```

Result:

| name  | department | salary | row_num |
| ----- | ---------- | -----: | ------: |
| Rahul | IT         |  70000 |       1 |
| Sahil | IT         |  50000 |       2 |
| Priya | HR         |  60000 |       1 |
| Amit  | HR         |  40000 |       2 |

Notice that numbering starts from `1` again for HR.

Conceptually:

```text
IT
  Rahul  → 1
  Sahil  → 2

HR
  Priya  → 1
  Amit   → 2
```

---

## Important: ROW_NUMBER() gives unique numbers

Suppose two employees have the same salary:

| name  | salary |
| ----- | -----: |
| Rahul |  70000 |
| Sahil |  70000 |
| Priya |  60000 |

```sql
ROW_NUMBER() OVER (
    ORDER BY salary DESC
)
```

might produce:

| name  | salary | row_num |
| ----- | -----: | ------: |
| Rahul |  70000 |       1 |
| Sahil |  70000 |       2 |
| Priya |  60000 |       3 |

Even though Rahul and Sahil have the same salary, they get **different row numbers**.

If the ordering column contains ties and you need deterministic results, add a unique tie-breaker:

```sql
ROW_NUMBER() OVER (
    ORDER BY salary DESC, id
)
```

This is an important production consideration.

---

## ROW_NUMBER() vs RANK()

This is a common interview question.

Suppose salaries are:

```text
70000
70000
60000
```

### `ROW_NUMBER()`

```text
1
2
3
```

Every row gets a unique number.

### `RANK()`

```text
1
1
3
```

Rows with equal values receive the same rank, and the next rank has a gap.

### `DENSE_RANK()`

```text
1
1
2
```

Rows with equal values receive the same rank, but there are no gaps.

| Function         | Ties get same value? | Unique number for every row? | Example     |
| ---------------- | -------------------- | ---------------------------- | ----------- |
| `ROW_NUMBER()` | ❌ No                | ✅ Yes                       | `1, 2, 3` |
| `RANK()`       | ✅ Yes               | ❌ No                        | `1, 1, 3` |
| `DENSE_RANK()` | ✅ Yes               | ❌ No                        | `1, 1, 2` |

## Practical Use Case: Top N per Group

One of the most common uses of `ROW_NUMBER()` is finding the **top N records within each group**.

For example:

> Find the top 2 highest-paid employees in each department.

```sql
WITH ranked_employees AS (
    SELECT
        name,
        department,
        salary,
        ROW_NUMBER() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) AS rn
    FROM employees
)
SELECT
    name,
    department,
    salary
FROM ranked_employees
WHERE rn <= 2;
```

The window function first numbers employees within each department:

```text
IT:
1 → highest salary
2 → second highest
3 → third highest

HR:
1 → highest salary
2 → second highest
3 → third highest
```

Then the outer query keeps only `rn <= 2`.

---

## Another Practical Use: Removing Duplicates

Suppose a table contains duplicate records and you want to keep one row from each duplicate group.

You can use:

```sql
ROW_NUMBER() OVER (
    PARTITION BY email
    ORDER BY id
)
```

For example:

```sql
WITH numbered AS (
    SELECT
        id,
        email,
        ROW_NUMBER() OVER (
            PARTITION BY email
            ORDER BY id
        ) AS rn
    FROM users
)
SELECT *
FROM numbered
WHERE rn = 1;
```

This keeps the first row for each email according to the chosen ordering.

In a real cleanup operation, you would carefully verify the duplicate criteria and deletion strategy before modifying production data.

---

## Important Point: `ROW_NUMBER()` doesn't physically add a column

The row number exists only in the **query result**.

It does not modify the table.

```sql
SELECT
    name,
    ROW_NUMBER() OVER (ORDER BY id) AS row_num
FROM employees;
```

`row_num` here is a calculated result, not a permanent column.

---

### Interview Takeaway

> **`ROW_NUMBER()` assigns a unique sequential number to each row based on the specified ordering. When combined with `PARTITION BY`, the numbering restarts for each group.**

Remember:

```text
ROW_NUMBER()
    ↓
Unique sequential number
    ↓
PARTITION BY → restart numbering for each group
    ↓
ORDER BY → decide the numbering order
```

The most common interview use case is:

**`ROW_NUMBER()` + `PARTITION BY` → Top N records per group**
