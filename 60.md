## 60. Find customers who have never placed an order

### Answer

The safest and most common approach is to use **`NOT EXISTS`**.

Assume we have:

```text
customers
- id
- name

orders
- id
- customer_id
- order_date
```

### Using `NOT EXISTS`

```sql
SELECT
    c.id,
    c.name
FROM customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.id
);
```

### How it works

For each customer, SQL checks:

> "Does an order exist for this customer?"

* If an order exists → customer is excluded.
* If no order exists → customer is returned.

For example:

| Customer | Orders |
| -------- | ------ |
| Rahul    | 3      |
| Amit     | 1      |
| Priya    | 0      |
| Neha     | 2      |

Result:

```text
Priya
```

---

### Using `LEFT JOIN`

Another very common interview solution is:

```sql
SELECT
    c.id,
    c.name
FROM customers c
LEFT JOIN orders o
    ON o.customer_id = c.id
WHERE o.id IS NULL;
```

The `LEFT JOIN` keeps **all customers**. Customers without a matching order get `NULL` values for the `orders` columns.

So:

```sql
WHERE o.id IS NULL
```

identifies customers who never placed an order.

### `NOT EXISTS` vs `LEFT JOIN`

Both can correctly solve this problem.

| Approach                  | Idea                                                       |
| ------------------------- | ---------------------------------------------------------- |
| `NOT EXISTS`            | Return customers for whom no matching order exists         |
| `LEFT JOIN ... IS NULL` | Keep all customers, then find those with no matching order |

`NOT EXISTS` is particularly expressive when the requirement is **"there is no related record."**

### Important interview trap: `NOT IN`

You may see:

```sql
SELECT *
FROM customers
WHERE id NOT IN (
    SELECT customer_id
    FROM orders
);
```

This can produce unexpected results if `orders.customer_id` contains `NULL`, because SQL's three-valued logic makes `NOT IN` behave differently in the presence of `NULL`.

For this type of question, **`NOT EXISTS` is generally the safer pattern**.

### Interview Takeaway

Remember this pattern:

```sql
SELECT *
FROM customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.id
);
```

**Key idea:** `NOT EXISTS` answers the question: **"Is there no matching record?**

## Answer

SQL databases store data in relational tables with fixed schemas and support SQL queries. NoSQL databases are non-relational systems that often use documents, key-value pairs, or graphs.

### Interview takeaway

Choose SQL when data relationships and transactions matter; choose NoSQL when scalability and flexible schemas are more important.

```text
SQL: relational, structured, ACID, schema-based
NoSQL: flexible, scalable, often document or key-value based
```
