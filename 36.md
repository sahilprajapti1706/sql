## 36. How would you find the top N records within each group?

### Answer

The most common approach is to use a **window function**, especially `ROW_NUMBER()`, `RANK()`, or `DENSE_RANK()`.

The important part is:

> **`PARTITION BY` creates the groups, and `ORDER BY` determines what "top" means within each group.**

Suppose we have an `employees` table:

| name   | department | salary |
| ------ | ---------- | -----: |
| Amit   | IT         | 100000 |
| Rahul  | IT         |  90000 |
| Priya  | IT         |  80000 |
| Neha   | IT         |  70000 |
| Raj    | HR         |  95000 |
| Anjali | HR         |  85000 |
| Karan  | HR         |  75000 |

If we want the **top 2 highest-paid employees from each department**:

### Using `ROW_NUMBER()`

```sql
WITH ranked AS (
    SELECT
        name,
        department,
        salary,
        ROW_NUMBER() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) AS rn
    FROM employees
)
SELECT
    name,
    department,
    salary
FROM ranked
WHERE rn <= 2;
```

Result:

| name   | department | salary |
| ------ | ---------- | -----: |
| Amit   | IT         | 100000 |
| Rahul  | IT         |  90000 |
| Raj    | HR         |  95000 |
| Anjali | HR         |  85000 |

### How it works

First:

```sql
PARTITION BY department
```

creates separate windows:

```text
IT → employees
HR → employees
```

Then:

```sql
ORDER BY salary DESC
```

sorts employees by salary within each department.

`ROW_NUMBER()` assigns numbers independently within each department:

```text
IT:
100000 → 1
90000  → 2
80000  → 3

HR:
95000 → 1
85000 → 2
75000 → 3
```

Finally:

```sql
WHERE rn <= 2
```

keeps only the top 2 from each group.

---

### What if there are ties?

This is an important interview consideration.

Suppose IT has:

```text
100000
90000
90000
80000
```

Using `ROW_NUMBER()`:

```text
100000 → 1
90000  → 2
90000  → 3
80000  → 4
```

Only one of the employees earning `90000` would be included when `rn <= 2`.

If you want **all employees tied at the Nth position**, use `RANK()`:

```sql
WITH ranked AS (
    SELECT
        name,
        department,
        salary,
        RANK() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) AS rnk
    FROM employees
)
SELECT *
FROM ranked
WHERE rnk <= 2;
```

With:

```text
100000 → rank 1
90000  → rank 2
90000  → rank 2
80000  → rank 4
```

both employees earning `90000` are returned.

### `ROW_NUMBER()` vs `RANK()` vs `DENSE_RANK()`

| Function         | Ties share rank? | Gaps? | Typical use                     |
| ---------------- | ---------------- | ----- | ------------------------------- |
| `ROW_NUMBER()` | No               | No    | Exactly N rows per group        |
| `RANK()`       | Yes              | Yes   | Top N positions, including ties |
| `DENSE_RANK()` | Yes              | No    | Top N distinct values           |

### Practical Example

For a franchise platform, suppose you want the **top 3 listings by views in each category**:

```sql
WITH ranked_listings AS (
    SELECT
        listing_id,
        category_id,
        views,
        ROW_NUMBER() OVER (
            PARTITION BY category_id
            ORDER BY views DESC
        ) AS rn
    FROM listings
)
SELECT
    listing_id,
    category_id,
    views
FROM ranked_listings
WHERE rn <= 3;
```

This gives **up to 3 listings per category**, rather than just 3 listings overall.

### Interview Takeaway

The standard pattern to remember is:

```sql
WITH ranked AS (
    SELECT
        *,
        ROW_NUMBER() OVER (
            PARTITION BY group_column
            ORDER BY ranking_column DESC
        ) AS rn
    FROM table_name
)
SELECT *
FROM ranked
WHERE rn <= N;
```

The key idea is:

> **`PARTITION BY` → define each group**
> **`ORDER BY` → define what "top" means**
> **window function → assign the position**
> **outer `WHERE` → keep the top**

## Answer

A trigger is a database object that automatically runs when a specific event occurs, such as `INSERT`, `UPDATE`, or `DELETE`.

```sql
CREATE TRIGGER audit_users
AFTER INSERT ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_log(message) VALUES ('User inserted');
END;
```

### Interview takeaway

Triggers are useful for auditing and automatic actions, but they can be harder to debug and maintain.
