## 46. What are the advantages and disadvantages of indexes?

### Answer

Indexes are additional data structures that help the database **find and access rows efficiently**. They can significantly improve read performance, but they also introduce storage and write-maintenance costs.

---

## Advantages of Indexes

### 1. Faster data retrieval

Indexes can make queries much faster by avoiding unnecessary table scans.

```sql
SELECT *
FROM users
WHERE email = 'sahil@example.com';
```

With an appropriate index on `email`, the database may locate the matching row much more efficiently.

---

### 2. Improve `WHERE` queries

Indexes are particularly useful for frequently filtered columns.

```sql
CREATE INDEX idx_users_email
ON users(email);
```

This can improve suitable queries such as:

```sql
SELECT *
FROM users
WHERE email = 'sahil@example.com';
```

---

### 3. Can improve JOIN performance

Indexes on columns used to connect tables can help the database efficiently locate matching rows.

For example:

```sql
CREATE INDEX idx_orders_user_id
ON orders(user_id);
```

can be useful for queries joining `orders` with `users`.

---

### 4. Can help with sorting

An appropriate index can sometimes allow the database to retrieve rows in the required order without performing a separate sort.

For example:

```sql
SELECT *
FROM listings
WHERE owner_id = 101
ORDER BY created_at DESC;
```

A suitable composite index such as:

```sql
CREATE INDEX idx_listings_owner_created
ON listings(owner_id, created_at DESC);
```

may help this query.

Whether it actually does depends on the database's query planner and the data distribution.

---

### 5. Can enforce uniqueness

A **unique index** can ensure that duplicate values aren't allowed.

```sql
CREATE UNIQUE INDEX idx_users_email
ON users(email);
```

Now two users cannot have the same email, subject to the database's handling of `NULL`.

In PostgreSQL, a `UNIQUE` constraint is generally backed by a unique index.

---

## Disadvantages of Indexes

### 1. Additional storage

Indexes consume disk space.

For a large table with several indexes, the indexes themselves can occupy significant storage.

```text
Table data
   +
Index 1
   +
Index 2
   +
Index 3
```

---

### 2. Slower INSERT operations

When a row is inserted, relevant indexes may also need to be updated.

```text
INSERT
  ↓
Update table
  ↓
Update indexes
```

The more indexes a table has, the more maintenance work may be required.

---

### 3. Slower UPDATE operations

If an indexed column changes, the corresponding index must also be maintained.

For example:

```sql
UPDATE users
SET email = 'new@example.com'
WHERE id = 101;
```

If `email` is indexed, the index needs to reflect the new value.

---

### 4. Slower DELETE operations

When rows are deleted, the corresponding index entries also need to be removed.

```sql
DELETE FROM users
WHERE id = 101;
```

So indexes add some overhead to write operations.

---

### 5. Too many indexes can hurt performance

Creating an index on every column is not a good strategy.

For example:

```text
users
 ├── id       → index
 ├── name     → index
 ├── email    → index
 ├── city     → index
 ├── age      → index
 ├── status   → index
 └── country  → index
```

Many of these indexes may provide little value while increasing:

* Storage usage
* Write overhead
* Maintenance work
* Planning complexity

Indexes should be based on **actual query patterns and workload**.

---

### 6. Indexes don't guarantee faster queries

The database optimizer may decide that an index isn't useful for a particular query.

For example, if a condition matches a very large percentage of the table, scanning the table may be cheaper than using the index and then fetching many rows.

You can investigate this with:

```sql
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE status = 'active';
```

---

## Advantages vs Disadvantages

| Advantages                    | Disadvantages                         |
| ----------------------------- | ------------------------------------- |
| Faster data retrieval         | Requires additional storage           |
| Can improve`WHERE` queries  | Can slow`INSERT`                    |
| Can improve suitable`JOIN`s | Can slow`UPDATE`                    |
| Can help with`ORDER BY`     | Can slow`DELETE`                    |
| Can enforce uniqueness        | Too many indexes can hurt performance |
| Useful for large datasets     | Doesn't guarantee faster queries      |

### Interview Takeaway

The key trade-off is:

> **Indexes improve read performance at the cost of storage and write performance.**

So in production, don't ask **"Which columns should I index?"** in isolation. Ask:

> **"Which queries are slow or frequent, and what index structure best supports those queries?"**
