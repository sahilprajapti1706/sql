
## 42. What are COMMIT and ROLLBACK?

### Answer

`COMMIT` and `ROLLBACK` are transaction-control commands used to control what happens to changes made during a database transaction.

* **`COMMIT`** → permanently save the transaction's changes.
* **`ROLLBACK`** → undo the transaction's uncommitted changes.

They are commonly used with:

```sql
BEGIN;
-- operations
COMMIT;
```

or:

```sql
BEGIN;
-- operations
ROLLBACK;
```

---

## 1. COMMIT

`COMMIT` successfully ends a transaction and makes its changes durable according to the database's transaction guarantees.

Example:

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 1000
WHERE id = 1;

UPDATE accounts
SET balance = balance + 1000
WHERE id = 2;

COMMIT;
```

After `COMMIT`, the changes made by the transaction are saved.

Conceptually:

```text
BEGIN
  ↓
UPDATE
  ↓
UPDATE
  ↓
COMMIT
  ↓
Changes saved
```

---

## 2. ROLLBACK

`ROLLBACK` aborts the transaction and undoes its **uncommitted changes**.

Example:

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 1000
WHERE id = 1;

UPDATE accounts
SET balance = balance + 1000
WHERE id = 2;

-- Something went wrong
ROLLBACK;
```

The changes made since the transaction began are rolled back.

Conceptually:

```text
BEGIN
  ↓
UPDATE
  ↓
UPDATE
  ↓
Error / Decision to cancel
  ↓
ROLLBACK
  ↓
Uncommitted changes undone
```

---

## 3. Practical Example

Suppose an application creates an order and decreases inventory:

```sql
BEGIN;

INSERT INTO orders (user_id, total)
VALUES (101, 2000);

UPDATE products
SET stock = stock - 1
WHERE id = 50
  AND stock > 0;
```

If everything succeeds:

```sql
COMMIT;
```

If something fails and the transaction should not be partially applied:

```sql
ROLLBACK;
```

This prevents the database from being left with only part of the intended operation committed.

---

## 4. COMMIT vs ROLLBACK

|                           | `COMMIT`               | `ROLLBACK`                         |
| ------------------------- | ------------------------ | ------------------------------------ |
| Purpose                   | Save transaction changes | Undo uncommitted transaction changes |
| Ends current transaction? | Yes                      | Yes                                  |
| Changes remain?           | Yes                      | No                                   |
| Typical use               | Everything succeeded     | Error/cancel occurred                |

---

## 5. Important Interview Point

`ROLLBACK` does **not** mean "undo any change ever made to the database."

It applies to changes that are still part of the **current uncommitted transaction**.

For example:

```sql
BEGIN;

UPDATE employees
SET salary = 90000
WHERE id = 10;

ROLLBACK;
```

The salary change is undone.

But:

```sql
BEGIN;

UPDATE employees
SET salary = 90000
WHERE id = 10;

COMMIT;

ROLLBACK;
```

The second `ROLLBACK` cannot undo the already committed change.

### Interview Takeaway

Remember:

> **`COMMIT` = "Keep my transaction changes."**
> **`ROLLBACK` = "Discard my uncommitted transaction changes."**

In application code, a common pattern is:

```text
BEGIN
   ↓
Perform related operations
   ↓
Success? ── Yes → COMMIT
   │
   No
   ↓
ROLLBACK
```
