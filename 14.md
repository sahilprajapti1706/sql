## 14. How does SQL handle NULL values?

### Answer

In SQL, **`NULL` means that a value is missing, unknown, or not applicable**.

It is important to understand that:

> **`NULL` is not `0`, not an empty string `''`, and not `FALSE`.**

For example:

| id | name  | phone          |
| -: | ----- | -------------- |
|  1 | Sahil | `9876543210` |
|  2 | Rahul | `NULL`       |
|  3 | Priya | `NULL`       |

For Rahul, `phone = NULL` means the phone value is unknown or missing.

---

## 1. You cannot compare `NULL` using `=`

This is a common mistake:

```sql
-- ❌ Incorrect
SELECT *
FROM users
WHERE phone = NULL;
```

Use `IS NULL` instead:

```sql
-- ✅ Correct
SELECT *
FROM users
WHERE phone IS NULL;
```

To find values that are present:

```sql
SELECT *
FROM users
WHERE phone IS NOT NULL;
```

### Why?

`NULL` represents an unknown value, so SQL cannot treat:

```sql
NULL = NULL
```

as `TRUE`.

Instead, comparisons involving `NULL` generally produce **`UNKNOWN`**.

---

# 2. SQL uses Three-Valued Logic

Normal Boolean logic has:

```text
TRUE
FALSE
```

SQL additionally has:

```text
UNKNOWN
```

For example:

```sql
salary > 50000
```

If `salary` is `NULL`, SQL cannot determine whether it is greater than 50,000.

So the result is:

```text
UNKNOWN
```

And when `WHERE` filters rows, only conditions evaluating to **TRUE** are returned.

This is why:

```sql
WHERE salary > 50000
```

doesn't return rows where `salary` is `NULL`.

---

# 3. `NULL` and Aggregate Functions

Most aggregate functions ignore `NULL` values.

Suppose:

| id |   salary |
| -: | -------: |
|  1 |    50000 |
|  2 |    60000 |
|  3 | `NULL` |

Then:

```sql
SELECT AVG(salary)
FROM employees;
```

calculates:

```text
(50000 + 60000) / 2
= 55000
```

The `NULL` salary is not treated as zero.

Similarly:

```sql
COUNT(salary)
```

counts only non-`NULL` salaries:

```text
2
```

while:

```sql
COUNT(*)
```

counts all rows:

```text
3
```

### Important exception

`COUNT(*)` counts rows, so it does not ignore rows just because some column contains `NULL`.

---

# 4. `NULL` with Arithmetic

Arithmetic involving `NULL` generally produces `NULL`.

For example:

```sql
SELECT 100 + NULL;
```

The result is:

```text
NULL
```

Similarly:

```sql
SELECT salary * 12
FROM employees;
```

If `salary` is `NULL`, the calculated result will also be `NULL`.

---

# 5. Handling `NULL` with `COALESCE()`

`COALESCE()` is commonly used to replace `NULL` with a fallback value.

```sql
SELECT
    name,
    COALESCE(phone, 'Not Provided') AS phone
FROM users;
```

If `phone` is `NULL`, the result becomes:

```text
Not Provided
```

Another example:

```sql
SELECT
    product_name,
    price,
    COALESCE(discount, 0) AS discount
FROM products;
```

If `discount` is `NULL`, SQL returns `0` for that expression.

### How `COALESCE()` works

```sql
COALESCE(value1, value2, value3)
```

returns the **first non-NULL value**.

For example:

```sql
SELECT COALESCE(NULL, NULL, 100, 200);
```

returns:

```text
100
```

---

# 6. `NULL` with `NOT IN`

There is an important edge case with `NOT IN`.

Suppose:

```sql
WHERE department NOT IN ('HR', 'Sales')
```

and `department` itself is `NULL`.

The result isn't simply "not HR and not Sales." Because comparisons with `NULL` produce `UNKNOWN`, that row won't satisfy the `WHERE` condition.

If you want to explicitly include missing departments, you could write:

```sql
WHERE department NOT IN ('HR', 'Sales')
   OR department IS NULL;
```

This is a common interview and production SQL trap.

---

# 7. `NULL` and `DISTINCT`

`DISTINCT` treats `NULL` values as duplicate values for the purpose of eliminating duplicate result rows.

For example:

```sql
SELECT DISTINCT department
FROM employees;
```

If the data contains:

```text
IT
HR
IT
NULL
NULL
```

the result will contain one `NULL` entry:

```text
IT
HR
NULL
```

---

# 8. `NULL` in Sorting

When using:

```sql
ORDER BY salary;
```

the exact placement of `NULL` values can depend on the database system and sort direction.

In PostgreSQL, you can explicitly control it:

```sql
ORDER BY salary ASC NULLS LAST;
```

or:

```sql
ORDER BY salary DESC NULLS FIRST;
```

This is useful when you need predictable ordering.

---

# 9. `NULL` vs Empty String vs Zero

These are different concepts:

| Value     | Meaning                        |
| --------- | ------------------------------ |
| `NULL`  | Missing/unknown/not applicable |
| `''`    | Empty string                   |
| `0`     | Numeric zero                   |
| `FALSE` | Boolean false                  |

For example:

```text
phone = NULL    → phone information is missing
phone = ''      → phone is an explicitly stored empty string
balance = 0     → balance is actually zero
active = FALSE  → explicitly inactive
```

The distinction matters when writing queries and designing databases.

---

## Practical Example

Suppose an `employees` table contains optional `bonus`:

| name  | salary |    bonus |
| ----- | -----: | -------: |
| Sahil |  50000 |     5000 |
| Rahul |  60000 | `NULL` |
| Priya |  70000 |    10000 |

If you want to calculate total compensation and treat a missing bonus as zero:

```sql
SELECT
    name,
    salary + COALESCE(bonus, 0) AS total_compensation
FROM employees;
```

Result:

| name  | total_compensation |
| ----- | -----------------: |
| Sahil |              55000 |
| Rahul |              60000 |
| Priya |              80000 |

Without `COALESCE()`, Rahul's calculation would result in `NULL`.

## Common Mistakes

### ❌ Comparing with `= NULL`

```sql
WHERE column = NULL
```

### ✅ Use

```sql
WHERE column IS NULL
```

---

### ❌ Assuming `NULL = 0`

It doesn't.

```text
NULL ≠ 0
```

---

### ❌ Assuming `NULL` means empty string

```text
NULL ≠ ''
```

---

### ❌ Assuming `COUNT(column)` counts every row

It doesn't. It ignores `NULL` values.

```text
COUNT(*)       → all rows
COUNT(column)  → non-NULL values
```

---

### Interview Takeaway

> **`NULL` represents a missing, unknown, or inapplicable value. It is not zero or an empty string. Use `IS NULL` / `IS NOT NULL` for checking it, and functions such as `COALESCE()` when you need to provide a fallback value.**

The most important points to remember:

```text
NULL comparison      → IS NULL / IS NOT NULL
NULL in arithmetic   → usually NULL
Aggregate functions  → generally ignore NULL
COUNT(*)             → counts rows
COUNT(column)        → counts non-NULL values
COALESCE()            → provides a fallback for NULL
WHERE + NULL         → condition becomes UNKNOWN
```

## Answer

`COUNT(*)` counts all rows, including duplicates and NULLs. `COUNT(column)` counts non-NULL values in that column. `COUNT(DISTINCT column)` counts unique non-NULL values.

```sql
SELECT COUNT(*) AS all_rows,
       COUNT(email) AS emails_present,
       COUNT(DISTINCT city) AS unique_cities
FROM users;
```

### Interview takeaway

These functions are often used in reporting and data quality checks.
