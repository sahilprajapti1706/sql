
## 38. Explain INSERT, UPDATE, and DELETE.

### Answer

`INSERT`, `UPDATE`, and `DELETE` are SQL commands used to **modify data stored in a table**.

They are part of **DML (Data Manipulation Language)**.

| Command    | Purpose              |
| ---------- | -------------------- |
| `INSERT` | Add new rows         |
| `UPDATE` | Modify existing rows |
| `DELETE` | Remove existing rows |

---

## 1. INSERT

`INSERT` is used to add new records to a table.

### Insert one row

```sql
INSERT INTO employees (name, department, salary)
VALUES ('Amit', 'IT', 70000);
```

This adds a new employee.

### Insert multiple rows

```sql
INSERT INTO employees (name, department, salary)
VALUES
    ('Rahul', 'HR', 60000),
    ('Priya', 'IT', 75000),
    ('Neha', 'Finance', 65000);
```

### Best practice

Specify the column names explicitly:

```sql
INSERT INTO employees (name, department, salary)
VALUES (...);
```

instead of relying on:

```sql
INSERT INTO employees
VALUES (...);
```

This makes the query safer and clearer if the table structure changes.

---

## 2. UPDATE

`UPDATE` modifies existing rows.

```sql
UPDATE employees
SET salary = 80000
WHERE id = 101;
```

This changes the salary only for the employee whose `id` is `101`.

You can update multiple columns:

```sql
UPDATE employees
SET
    salary = 85000,
    department = 'Engineering'
WHERE id = 101;
```

### ⚠️ Important: `WHERE` matters

Consider:

```sql
UPDATE employees
SET salary = 80000;
```

Without a `WHERE` clause, **every row** in the table will be updated.

This is one of the most common and dangerous SQL mistakes.

---

## 3. DELETE

`DELETE` removes rows from a table.

```sql
DELETE FROM employees
WHERE id = 101;
```

This deletes the employee whose `id` is `101`.

You can delete multiple rows:

```sql
DELETE FROM employees
WHERE department = 'HR';
```

### ⚠️ Without `WHERE`

```sql
DELETE FROM employees;
```

This removes **all rows from the table**.

The table itself still exists, but its rows are deleted.

---

## 4. INSERT vs UPDATE vs DELETE

Suppose we start with:

| id | name  | salary |
| -: | ----- | -----: |
|  1 | Amit  |  70000 |
|  2 | Rahul |  60000 |

### INSERT

```sql
INSERT INTO employees (id, name, salary)
VALUES (3, 'Priya', 75000);
```

Result: a **new row** is added.

### UPDATE

```sql
UPDATE employees
SET salary = 80000
WHERE id = 1;
```

Result: Amit's existing row is **modified**.

### DELETE

```sql
DELETE FROM employees
WHERE id = 2;
```

Result: Rahul's row is **removed**.

---

## 5. Using Transactions Safely

For important updates/deletes, transactions can help prevent accidental changes.

```sql
BEGIN;

UPDATE employees
SET salary = 80000
WHERE department = 'IT';

-- Check the result

ROLLBACK;
```

If everything looks correct:

```sql
COMMIT;
```

* `COMMIT` → permanently save the transaction's changes.
* `ROLLBACK` → undo the uncommitted changes.

In production systems, transactions are especially important when multiple related changes must succeed or fail together.

---

## 6. Practical Application Example

In a backend application, you might have:

```sql
INSERT INTO users (name, email)
VALUES ($1, $2);
```

where `$1` and `$2` are supplied as **parameters** by the application.

Using parameterized queries is important because it helps prevent **SQL injection**.

Similarly:

```sql
UPDATE users
SET name = $1
WHERE id = $2;
```

and:

```sql
DELETE FROM users
WHERE id = $1;
```

---

### Interview Takeaway

Remember:

```text
INSERT → Add rows
UPDATE → Modify rows
DELETE → Remove rows
```

And the most important practical rule:

> **Always carefully verify the `WHERE` clause of `UPDATE` and `DELETE` statements.** A missing or incorrect condition can modify or delete far more data than intended.
