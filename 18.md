## 18. Explain LEFT JOIN

### Answer

A **`LEFT JOIN`** returns:

1. **All rows from the left table**, and
2. Matching rows from the right table.

If there is **no matching row** in the right table, SQL still returns the left-table row, but the right-table columns contain `NULL`.

> **LEFT JOIN = Keep everything from the left table, and add matching data from the right table.**

---

## Example

Suppose we have:

### `users`

| id | name  |
| -: | ----- |
|  1 | Sahil |
|  2 | Rahul |
|  3 | Priya |
|  4 | Ankit |

### `orders`

|  id | user_id | amount |
| --: | ------: | -----: |
| 101 |       1 |    500 |
| 102 |       2 |    800 |
| 103 |       1 |   1200 |

Now:

```sql
SELECT
    u.name,
    o.amount
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id;
```

### Result

| name  | amount |
| ----- | -----: |
| Sahil |    500 |
| Sahil |   1200 |
| Rahul |    800 |
| Priya |   NULL |
| Ankit |   NULL |

Notice:

* Sahil has two matching orders → two rows.
* Rahul has one matching order → one row.
* Priya has no order → still appears, with `NULL`.
* Ankit has no order → still appears, with `NULL`.

This is the key difference from `INNER JOIN`.

---

# How LEFT JOIN Works

Think of it as:

```text
LEFT TABLE                  RIGHT TABLE

users                       orders

1  Sahil  ───────────────→  1  500
2  Rahul  ───────────────→  2  800
3  Priya  ── no match
4  Ankit  ── no match
                            1  1200
```

The rule is:

```text
Every row from LEFT table
          +
Matching rows from RIGHT table
          ↓
Final result
```

For unmatched rows:

```text
right_table_column = NULL
```

---

# Syntax

```sql
SELECT columns
FROM left_table
LEFT JOIN right_table
    ON left_table.column = right_table.column;
```

Example:

```sql
SELECT
    u.name,
    o.amount
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id;
```

Here:

* `users` → left table
* `orders` → right table
* `u.id = o.user_id` → matching condition

---

# Why is LEFT JOIN useful?

LEFT JOIN is useful when you want **all records from one table regardless of whether related data exists**.

### Example: Find all users and their orders

```sql
SELECT u.name, o.id AS order_id
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id;
```

This includes users who have never placed an order.

---

## Finding Users With No Orders

This is one of the most common practical uses of `LEFT JOIN`.

```sql
SELECT u.id, u.name
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id
WHERE o.id IS NULL;
```

The JOIN first keeps all users.

For users without orders:

```text
o.id = NULL
```

Then:

```sql
WHERE o.id IS NULL
```

keeps only those users.

So the query means:

> "Give me users for whom no matching order exists."

This pattern is often called an **anti-join pattern**.

---

# LEFT JOIN vs INNER JOIN

| `INNER JOIN`                      | `LEFT JOIN`                                       |
| ----------------------------------- | --------------------------------------------------- |
| Returns only matching rows          | Returns all left-table rows                         |
| Unmatched left rows are removed     | Unmatched left rows are retained                    |
| No-match right columns don't appear | No-match right columns become`NULL`               |
| Useful when a match is required     | Useful when the left entity must always be included |

Example:

### INNER JOIN

```sql
FROM users u
INNER JOIN orders o
    ON u.id = o.user_id
```

> Users **who have orders**

### LEFT JOIN

```sql
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id
```

> **All users**, with orders where available

---

# A Very Important LEFT JOIN Trap

Consider:

```sql
SELECT u.name, o.amount
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id
WHERE o.amount > 500;
```

You might think this means:

> "Give me all users and their orders above 500."

But the `WHERE` condition removes rows where `o.amount` is `NULL`.

Therefore, users without orders disappear.

In effect, this can behave much like an inner join for that condition.

If your intention is to keep all users while only matching orders above 500, put the condition in the `ON` clause:

```sql
SELECT u.name, o.amount
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id
   AND o.amount > 500;
```

Now users without qualifying orders remain with `NULL` order columns.

### This distinction is important in real applications.

---

# LEFT JOIN with Aggregation

Suppose you want **every user and their order count**, including users with zero orders:

```sql
SELECT
    u.id,
    u.name,
    COUNT(o.id) AS order_count
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id
GROUP BY u.id, u.name;
```

Result could be:

| id | name  | order_count |
| -: | ----- | ----------: |
|  1 | Sahil |           2 |
|  2 | Rahul |           1 |
|  3 | Priya |           0 |
|  4 | Ankit |           0 |

This is a very common reporting/dashboard query.

Notice we use:

```sql
COUNT(o.id)
```

rather than `COUNT(*)`.

For a user with no matching order, the LEFT JOIN still creates a result row, but `o.id` is `NULL`. Therefore `COUNT(o.id)` gives `0`.

---

## Interview Takeaway

> **A LEFT JOIN keeps every row from the left table and adds matching rows from the right table. If no match exists, the right-side columns contain `NULL`.**

Remember:

```text
INNER JOIN → only matches

LEFT JOIN
    ↓
all left rows
    +
matching right rows
    +
NULL when no match
```

A very common interview example is:

```sql
SELECT u.name
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id
WHERE o.id IS NULL;
```

which finds:

> **Users who have no order**

## Answer

A `RIGHT JOIN` keeps all rows from the right table and includes matching rows from the left table. A `FULL OUTER JOIN` keeps rows from both sides, even when a match is missing.

```sql
SELECT *
FROM users u
FULL OUTER JOIN orders o
  ON u.id = o.user_id;
```

### Interview takeaway

These joins are useful when you need to inspect unmatched records from both tables.
