## 34. What are PARTITION BY and ORDER BY inside a window function?

### Answer

Inside a window function, `PARTITION BY` and `ORDER BY` control **which rows the function considers** and **in what order it processes them**.

A useful mental model is:

> **`PARTITION BY` → divides rows into groups**
> **`ORDER BY` → decides the order within each group**

They are commonly used together.

### Basic Syntax

```sql
function_name() OVER (
    PARTITION BY column
    ORDER BY column
)
```

---

### 1. `PARTITION BY`

`PARTITION BY` divides the result set into separate **windows/groups**.

The window function is then calculated independently within each partition.

For example:

```sql
SELECT
    name,
    department,
    salary,
    AVG(salary) OVER (
        PARTITION BY department
    ) AS department_avg_salary
FROM employees;
```

Suppose we have:

| name  | department | salary |
| ----- | ---------- | -----: |
| Amit  | IT         |  80000 |
| Rahul | IT         |  60000 |
| Priya | HR         |  70000 |
| Neha  | HR         |  50000 |

`PARTITION BY department` creates two windows:

```text
IT → Amit, Rahul
HR → Priya, Neha
```

The average is calculated separately for each department:

| name  | department | salary | department_avg_salary |
| ----- | ---------- | -----: | --------------------: |
| Amit  | IT         |  80000 |                 70000 |
| Rahul | IT         |  60000 |                 70000 |
| Priya | HR         |  70000 |                 60000 |
| Neha  | HR         |  50000 |                 60000 |

### Important point

`PARTITION BY` **does not collapse rows** like `GROUP BY` does.

All employees remain in the result.

---

### 2. `ORDER BY`

`ORDER BY` inside a window function determines the **order of rows within the window**.

For example:

```sql
SELECT
    name,
    salary,
    ROW_NUMBER() OVER (
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
```

The rows are considered in descending salary order:

```text
80000 → 1
70000 → 2
60000 → 3
50000 → 4
```

This is different from the query-level:

```sql
ORDER BY salary DESC;
```

The window `ORDER BY` controls **how the window function calculates its result**, while the final query `ORDER BY` controls **the order in which the final result is displayed**.

---

### 3. Using `PARTITION BY` and `ORDER BY` Together

This is where window functions become especially useful.

```sql
SELECT
    name,
    department,
    salary,
    RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS department_rank
FROM employees;
```

Suppose:

| name  | department | salary |
| ----- | ---------- | -----: |
| Amit  | IT         |  80000 |
| Rahul | IT         |  60000 |
| Priya | HR         |  70000 |
| Neha  | HR         |  50000 |

The database conceptually creates:

```text
IT
 ├── Amit   80000 → rank 1
 └── Rahul  60000 → rank 2

HR
 ├── Priya  70000 → rank 1
 └── Neha   50000 → rank 2
```

Result:

| name  | department | salary | department_rank |
| ----- | ---------- | -----: | --------------: |
| Amit  | IT         |  80000 |               1 |
| Rahul | IT         |  60000 |               2 |
| Priya | HR         |  70000 |               1 |
| Neha  | HR         |  50000 |               2 |

So:

* `PARTITION BY department` → **rank separately for each department**
* `ORDER BY salary DESC` → **highest salary gets the highest position**

---

### 4. What if `PARTITION BY` is omitted?

Without `PARTITION BY`, the entire result set is treated as **one window**.

```sql
RANK() OVER (
    ORDER BY salary DESC
)
```

All employees compete in the same ranking.

With:

```sql
RANK() OVER (
    PARTITION BY department
    ORDER BY salary DESC
)
```

employees compete only against others in their own department.

---

### 5. What if `ORDER BY` is omitted?

It depends on the window function.

For functions such as:

```sql
AVG(salary) OVER (
    PARTITION BY department
)
```

an order isn't needed because we are calculating the average for the entire partition.

But ranking functions such as `ROW_NUMBER()`, `RANK()`, and `DENSE_RANK()` need an ordering to determine the ranking.

For example:

```sql
ROW_NUMBER() OVER (
    PARTITION BY department
    ORDER BY salary DESC
)
```

---

### `GROUP BY` vs `PARTITION BY`

This is a common interview point.

**`GROUP BY` collapses rows:**

```sql
SELECT
    department,
    AVG(salary)
FROM employees
GROUP BY department;
```

Result:

| department |   avg |
| ---------- | ----: |
| IT         | 70000 |
| HR         | 60000 |

Only one row per department.

**`PARTITION BY` keeps the original rows:**

```sql
SELECT
    name,
    department,
    salary,
    AVG(salary) OVER (
        PARTITION BY department
    ) AS avg_salary
FROM employees;
```

Result:

| name  | department | salary | avg_salary |
| ----- | ---------- | -----: | ---------: |
| Amit  | IT         |  80000 |      70000 |
| Rahul | IT         |  60000 |      70000 |
| Priya | HR         |  70000 |      60000 |
| Neha  | HR         |  50000 |      60000 |

### Interview Takeaway

Remember:

> **`PARTITION BY` = "Which rows should be considered together?"**
> **`ORDER BY` = "In what order should those rows be processed/ranked?"**

For example:

```sql
RANK() OVER (
    PARTITION BY department
    ORDER BY salary DESC
)
```

means:

> **Rank employees separately within each department, from highest salary to lowes**

## Answer

A view is a virtual table created from a query. It does not store data itself but exposes a saved result set.

```sql
CREATE VIEW active_users AS
SELECT * FROM users WHERE status = 'active';
```

### Interview takeaway

Views simplify complex queries, improve reusability, and can hide sensitive columns from users.
