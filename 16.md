## 16. What is a JOIN and why is it needed?

### Answer

A **`JOIN`** is used to combine related data from **two or more tables** based on a related column or condition.

JOINs are needed because in a well-designed relational database, related information is usually stored in **separate tables** rather than putting everything into one large table.

---

## Why do we need JOINs?

Suppose we have two tables.

### `users`

| id | name  |
| -: | ----- |
|  1 | Sahil |
|  2 | Rahul |
|  3 | Priya |

### `orders`

|  id | user_id | amount |
| --: | ------: | -----: |
| 101 |       1 |    500 |
| 102 |       2 |    800 |
| 103 |       1 |   1200 |

Here:

```text
users.id  ←→  orders.user_id
```

`orders.user_id` is a foreign key referencing `users.id`.

If we want to answer:

> "What is each user's name and the amount of their order?"

The required information exists in **two different tables**.

A JOIN lets us combine them:

```sql
SELECT
    users.name,
    orders.amount
FROM users
JOIN orders
    ON users.id = orders.user_id;
```

Result:

| name  | amount |
| ----- | -----: |
| Sahil |    500 |
| Rahul |    800 |
| Sahil |   1200 |

---

# How a JOIN Works

The important part is:

```sql
ON users.id = orders.user_id
```

SQL compares the values from both tables and combines rows where the condition is satisfied.

Conceptually:

```text
users                    orders
─────                    ──────
id  name                 user_id  amount
1   Sahil      ───────→  1        500
2   Rahul      ───────→  2        800
3   Priya
                       1        1200
```

The JOIN creates a combined result based on the relationship.

---

## Why not store everything in one table?

You could theoretically create:

```text
orders
------------------------------------------------
order_id | user_name | user_phone | amount
```

But if a user has 100 orders, their name and phone may be repeated 100 times.

This creates:

* Data duplication
* Larger storage requirements
* Update anomalies
* Greater chance of inconsistent data

Instead, we can keep:

```text
users
─────
id
name
phone

orders
──────
id
user_id
amount
```

and use JOINs when we need information from both.

This works together with **normalization**.

---

# Common Types of JOIN

The major JOIN types are:

```text
INNER JOIN
LEFT JOIN
RIGHT JOIN
FULL OUTER JOIN
CROSS JOIN
```

There is also a **SELF JOIN**, where a table is joined with itself.

The most commonly used in application development are **INNER JOIN** and **LEFT JOIN**.

---

## 1. INNER JOIN

Returns only rows where a match exists in **both tables**.

```sql
SELECT users.name, orders.amount
FROM users
INNER JOIN orders
    ON users.id = orders.user_id;
```

If Priya has no order, Priya will not appear in the result.

Think:

```text
Table A ∩ Table B
```

Only matching records.

---

## 2. LEFT JOIN

Returns **all rows from the left table**, even if there is no matching row in the right table.

```sql
SELECT users.name, orders.amount
FROM users
LEFT JOIN orders
    ON users.id = orders.user_id;
```

If Priya has no order:

| name  | amount |
| ----- | -----: |
| Sahil |    500 |
| Rahul |    800 |
| Sahil |   1200 |
| Priya |   NULL |

The `NULL` means there was no matching order.

This is extremely useful for queries like:

> "Find all users, including users who haven't placed an order."

---

# JOIN and Foreign Keys

A JOIN **does not require a foreign key constraint**, although foreign keys are commonly used to represent the relationship between the tables.

For example:

```sql
users.id = orders.user_id
```

The database can JOIN using this condition even if a formal foreign key constraint wasn't defined.

The foreign key provides **data integrity**, while the JOIN is used to **retrieve related data**.

---

# Real-World Example

In an application, you might have:

```text
users
listings
applications
```

An `applications` table might contain:

```text
application_id
user_id
listing_id
status
```

You could retrieve the investor's name and listing title:

```sql
SELECT
    users.name AS investor_name,
    listings.title AS listing_title,
    applications.status
FROM applications
JOIN users
    ON applications.user_id = users.id
JOIN listings
    ON applications.listing_id = listings.id;
```

This is one of the main reasons relational databases are powerful: you can keep entities separate and combine them when needed.

---

## JOIN vs Relationship

These concepts are related but different:

**Relationship:**

```text
users.id ←→ orders.user_id
```

describes how the data is related.

**JOIN:**

```sql
JOIN orders
ON users.id = orders.user_id
```

is the SQL operation used to retrieve data based on that relationship.

## Interview Takeaway

> **A JOIN combines rows from multiple tables based on a related condition, allowing normalized relational data to be queried together.**

Remember:

```text
INNER JOIN → matching rows from both tables
LEFT JOIN  → everything from left + matching right
RIGHT JOIN → everything from right + matching left
FULL JOIN  → everything from both sides
```
