## 22. What is a self join?

### Answer

A **SELF JOIN** is a join where a table is **joined with itself**.

It is useful when rows in the same table have a relationship with other rows in that same table.

SQL does not have a separate `SELF JOIN` keyword. You simply use a normal `JOIN` and give the same table **different aliases**.

### Syntax

```sql
SELECT ...
FROM table_name t1
JOIN table_name t2
    ON t1.column = t2.column;
```

The aliases are important because SQL needs to distinguish between the two instances of the same table.

### Example: Employee and Manager

Suppose we have an `employees` table:

| id | name  | manager_id |
| -: | ----- | ---------: |
|  1 | Raj   |       NULL |
|  2 | Sahil |          1 |
|  3 | Rahul |          1 |
|  4 | Priya |          2 |

Here, `manager_id` refers to another employee's `id`.

We can use a self join to find each employee's manager:

```sql
SELECT
    e.name AS employee,
    m.name AS manager
FROM employees e
LEFT JOIN employees m
    ON e.manager_id = m.id;
```

Result:

| employee | manager |
| -------- | ------- |
| Raj      | NULL    |
| Sahil    | Raj     |
| Rahul    | Raj     |
| Priya    | Sahil   |

### How does it work?

The same `employees` table is treated as two logical copies:

```text
employees e                employees m
-------------              -------------
id   name   manager_id     id   name
1    Raj    NULL           1    Raj
2    Sahil  1              2    Sahil
3    Rahul  1              3    Rahul
4    Priya  2              4    Priya
```

The join condition:

```sql
e.manager_id = m.id
```

means:

> "Find the employee whose `id` matches this employee's `manager_id`."

### Common Use Cases

Self joins are commonly used for hierarchical or relationship-based data such as:

* Employee → Manager
* Employee → Supervisor
* Category → Parent Category
* Employee → Mentor
* Organization → Parent Organization

They can also be used to compare rows within the same table.

For example, finding pairs of employees who belong to the same department:

```sql
SELECT
    e1.name AS employee1,
    e2.name AS employee2
FROM employees e1
JOIN employees e2
    ON e1.department_id = e2.department_id
   AND e1.id < e2.id;
```

The `e1.id < e2.id` condition prevents getting both:

```text
Sahil - Rahul
Rahul - Sahil
```

and also prevents an employee from being paired with themselves.

### Interview Takeaway

> **A self join is a join where a table is joined with itself, usually using different aliases, to compare or relate rows within the same table.**

**Remember:**
**Self Join = Same table + different aliases + relationship between its rows**

## Answer

A correlated subquery depends on values from the outer query. It is evaluated once per row processed by the outer query.

```sql
SELECT e.name
FROM employees e
WHERE e.salary > (
    SELECT AVG(salary)
    FROM employees
    WHERE department = e.department
);
```

### Interview takeaway

Correlated subqueries can be powerful but may be slower because they re-execute for each row.
