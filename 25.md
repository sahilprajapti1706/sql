## 25. What is the difference between correlated and non-correlated subqueries?

### Answer

The main difference is:

> **A non-correlated subquery works independently of the outer query, while a correlated subquery depends on the outer query.**

---

### 1. Non-Correlated Subquery

A **non-correlated subquery** does **not reference columns from the outer query**.

It can be understood independently.

Example:

> Find employees whose salary is greater than the average salary of all employees.

```sql
SELECT name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

The inner query:

```sql
SELECT AVG(salary)
FROM employees;
```

doesn't use anything from the outer query.

So it is **non-correlated**.

#### Mental model

```text
Subquery
   ↓
Calculate average salary
   ↓
Outer query uses that value
```

The subquery is independent of individual rows being processed by the outer query.

---

### 2. Correlated Subquery

A **correlated subquery** references a column from the outer query.

Example:

> Find employees whose salary is greater than the average salary of their own department.

```sql
SELECT e.name, e.salary, e.department_id
FROM employees e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e2.department_id = e.department_id
);
```

Notice:

```sql
WHERE e2.department_id = e.department_id
```

`e.department_id` comes from the **outer query**.

Therefore, the subquery is **correlated** with the outer query.

#### Mental model

```text
Outer employee
      ↓
Find average salary for that employee's department
      ↓
Compare employee's salary
      ↓
Move to next employee
```

---

## Key Difference

| Feature                         | Non-Correlated            | Correlated                      |
| ------------------------------- | ------------------------- | ------------------------------- |
| Depends on outer query?         | ❌ No                     | ✅ Yes                          |
| References outer query columns? | ❌ No                     | ✅ Yes                          |
| Can run independently?          | ✅ Yes                    | ❌ No                           |
| Typical use                     | Global calculation/filter | Row-specific calculation/filter |
| Example                         | Salary > overall average  | Salary > department average     |

---

## Another Example with `EXISTS`

Correlated subqueries are commonly used with `EXISTS`.

```sql
SELECT c.name
FROM customers c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.id
);
```

Here:

```sql
o.customer_id = c.id
```

uses `c.id` from the outer query.

Therefore, this is a **correlated subquery**.

It effectively asks:

> "For this customer, does at least one matching order exist?"

---

## Important Performance Point

A common interview explanation is:

> "A correlated subquery always runs once for every outer row."

That is a useful **conceptual model**, but it is not necessarily how the database executes it.

The optimizer may transform the query into another execution strategy. Therefore, for performance-sensitive queries, check the execution plan rather than assuming the subquery literally executes once per row.

For example, in PostgreSQL:

```sql
EXPLAIN ANALYZE
SELECT ...
```

can help determine what actually happened.

---

## When should you use each?

### Use a non-correlated subquery when:

You need a value or set of values that doesn't depend on the current outer row.

Example:

```sql
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
)
```

### Use a correlated subquery when:

The condition needs to be evaluated relative to the **current row**.

Example:

```sql
WHERE salary > (
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e2.department_id = e.department_id
)
```

---

### Interview Takeaway

> **Non-correlated subquery:** independent of the outer query.
> **Correlated subquery:** references the outer query and depends on the current outer row.

The easiest way to identify one:

**Does the inner query reference an alias/column from the outer query?**

* **No → Non-correlated**
* **Yes → Correlat**

## Answer

`CASE` allows conditional logic inside a query. It is similar to `if-else` in programming languages.

```sql
SELECT name,
       CASE
           WHEN salary >= 100000 THEN 'High'
           WHEN salary >= 50000 THEN 'Medium'
           ELSE 'Low'
       END AS salary_band
FROM employees;
```

### Interview takeaway

`CASE` is extremely useful for bucketing, labeling, and deriving custom business logic in queries.
