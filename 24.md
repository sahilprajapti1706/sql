## 24. What is a subquery?

### Answer

A **subquery** is a SQL query written **inside another SQL query**.

The inner query is called the **subquery**, and the outer query uses its result to perform some operation.

Think of it as:

```text
Outer Query
    ↓
uses the result of
    ↓
Subquery
```

### Basic Example

Suppose we have an `employees` table:

| id | name  | salary |
| -: | ----- | -----: |
|  1 | Sahil |  50000 |
|  2 | Rahul |  70000 |
|  3 | Priya |  60000 |

Suppose we want to find employees earning **more than the average salary**.

First, we need the average salary:

```sql
SELECT AVG(salary)
FROM employees;
```

Instead of running this separately, we can put it inside another query:

```sql
SELECT name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

Here:

```sql
(
    SELECT AVG(salary)
    FROM employees
)
```

is the **subquery**.

The database conceptually gets the average salary first, then uses that value in the outer query.

---

## Why are subqueries useful?

They are useful when one query's result is needed by another query.

Common situations include:

* Comparing a value against an aggregate
* Checking whether related records exist
* Filtering using another query's results
* Finding records above/below some calculated value
* Breaking a complex problem into logical steps

---

## Types of Subqueries

### 1. Scalar Subquery

Returns **one value**.

Example:

```sql
SELECT name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

The `AVG()` subquery returns one value.

---

### 2. Multi-row Subquery

Returns **multiple values**.

For example, find employees who work in departments located in Delhi:

```sql
SELECT name
FROM employees
WHERE department_id IN (
    SELECT id
    FROM departments
    WHERE location = 'Delhi'
);
```

The inner query may return multiple department IDs, so `IN` is appropriate.

---

### 3. Correlated Subquery

A **correlated subquery** depends on a value from the outer query.

Example:

> Find employees whose salary is greater than the average salary of their own department.

```sql
SELECT e.name, e.salary, e.department_id
FROM employees e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e2.department_id = e.department_id
);
```

The important part is:

```sql
WHERE e2.department_id = e.department_id
```

The inner query refers to `e` from the outer query.

Conceptually:

```text
For each employee
      ↓
Find average salary of their department
      ↓
Compare employee's salary with that average
```

Correlated subqueries can be powerful, but depending on the query and database, a `JOIN` or window function may be a better approach for performance or readability.

---

## Subquery with EXISTS

`EXISTS` checks whether the subquery returns **at least one row**.

Example:

> Find customers who have placed at least one order.

```sql
SELECT c.id, c.name
FROM customers c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.id
);
```

You don't care about the actual value returned by the subquery. You only care whether a matching order exists.

---

## Subquery vs JOIN

Sometimes the same problem can be solved using either a subquery or a `JOIN`.

For example:

**Using a subquery:**

```sql
SELECT name
FROM employees
WHERE department_id IN (
    SELECT id
    FROM departments
    WHERE location = 'Delhi'
);
```

**Using a JOIN:**

```sql
SELECT e.name
FROM employees e
JOIN departments d
    ON e.department_id = d.id
WHERE d.location = 'Delhi';
```

Neither is automatically "better" in every situation.

Choose based on:

* What makes the logic clearer
* Whether you need columns from the other table
* Query complexity
* Database optimizer behavior
* Performance on the actual data

Modern databases can optimize many subqueries effectively, so don't assume that every subquery is slow.

---

## Common Interview Mistake

A subquery is **not necessarily executed once and then stored permanently**.

For a simple non-correlated subquery, you can mentally think of it as producing a result that the outer query uses. But the actual execution strategy is determined by the database optimizer.

For correlated subqueries especially, don't assume a literal "run the inner query once for every row" execution without checking the execution plan.

`UNION` combines the result sets of two queries and removes duplicate rows. `UNION ALL` combines them without removing duplicates.

```sql
SELECT id, name FROM customers
```

### Interview takeaway
