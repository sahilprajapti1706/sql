## 10. How do ORDER BY, GROUP BY, and DISTINCT work?

These three SQL clauses/operators solve different problems:

* **`ORDER BY`** → sorts the result.
* **`GROUP BY`** → combines rows into groups, usually for aggregation.
* **`DISTINCT`** → removes duplicate rows from the result.

---

## 1. `ORDER BY`

`ORDER BY` is used to **sort query results** based on one or more columns or expressions.

### Example

```sql
SELECT name, salary
FROM employees
ORDER BY salary;
```

By default, sorting is **ascending (`ASC`)**:

```text
30000
40000
50000
60000
```

For descending order:

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC;
```

### Multiple columns

You can sort using multiple criteria:

```sql
SELECT name, department, salary
FROM employees
ORDER BY department ASC, salary DESC;
```

This means:

1. Sort employees by department alphabetically.
2. Within each department, sort salary from highest to lowest.

### Important point

`ORDER BY` **does not change the data in the table**. It only changes the order of the returned result.

---

# 2. `GROUP BY`

`GROUP BY` is used to **group rows that have the same value** in one or more columns.

It is commonly used with aggregate functions such as:

* `COUNT()`
* `SUM()`
* `AVG()`
* `MIN()`
* `MAX()`

Suppose:

| id | department | salary |
| -: | ---------- | -----: |
|  1 | IT         |  50000 |
|  2 | IT         |  60000 |
|  3 | HR         |  40000 |
|  4 | HR         |  45000 |
|  5 | Sales      |  55000 |

To find the number of employees in each department:

```sql
SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department;
```

Result:

| department | employee_count |
| ---------- | -------------: |
| IT         |              2 |
| HR         |              2 |
| Sales      |              1 |

### Another example

Find the average salary of each department:

```sql
SELECT department, AVG(salary) AS average_salary
FROM employees
GROUP BY department;
```

Conceptually:

```text
IT
 ├── 50000
 └── 60000
     ↓
   AVG = 55000

HR
 ├── 40000
 └── 45000
     ↓
   AVG = 42500
```

### Key idea

`GROUP BY` changes the level at which you're looking at the data.

Without `GROUP BY`:

```sql
SELECT AVG(salary)
FROM employees;
```

You get **one average for the entire table**.

With:

```sql
SELECT department, AVG(salary)
FROM employees
GROUP BY department;
```

You get **one average per department**.

---

# 3. `DISTINCT`

`DISTINCT` removes duplicate rows from the query result.

Suppose:

| employee | department |
| -------- | ---------- |
| A        | IT         |
| B        | HR         |
| C        | IT         |
| D        | Sales      |
| E        | HR         |

If you want the list of unique departments:

```sql
SELECT DISTINCT department
FROM employees;
```

Result:

| department |
| ---------- |
| IT         |
| HR         |
| Sales      |

Without `DISTINCT`:

```sql
SELECT department
FROM employees;
```

you would get:

```text
IT
HR
IT
Sales
HR
```

### `DISTINCT` with multiple columns

```sql
SELECT DISTINCT department, job_role
FROM employees;
```

Here, SQL removes duplicate **combinations** of `department` and `job_role`.

For example:

| department | job_role  |
| ---------- | --------- |
| IT         | Developer |
| IT         | Developer |
| IT         | Tester    |
| HR         | Recruiter |

becomes:

| department | job_role  |
| ---------- | --------- |
| IT         | Developer |
| IT         | Tester    |
| HR         | Recruiter |

It does **not** mean that each individual column is independently unique.

---

# `ORDER BY` vs `GROUP BY` vs `DISTINCT`

| Feature                 | `ORDER BY`      | `GROUP BY`                  | `DISTINCT`             |
| ----------------------- | ----------------- | ----------------------------- | ------------------------ |
| Main purpose            | Sort results      | Create groups                 | Remove duplicates        |
| Changes number of rows? | Usually no        | Often yes                     | Yes, if duplicates exist |
| Commonly used with      | `ASC`, `DESC` | `COUNT`, `SUM`, `AVG`   | `SELECT`               |
| Aggregation required?   | No                | No, but commonly used with it | No                       |
| Example                 | Sort by salary    | Salary per department         | Unique departments       |

---

## Using them together

They can be combined in one query.

For example, find departments having at least 2 employees and sort them by employee count:

```sql
SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department
HAVING COUNT(*) >= 2
ORDER BY employee_count DESC;
```

Conceptually:

```text
FROM
  ↓
WHERE
  ↓
GROUP BY
  ↓
HAVING
  ↓
SELECT
  ↓
DISTINCT
  ↓
ORDER BY
```

The exact SQL processing rules have some nuances, but this is a useful **logical-order mental model** for interviews.

---

## A common confusion: `GROUP BY` vs `DISTINCT`

If you only need unique values:

```sql
SELECT DISTINCT department
FROM employees;
```

is usually the natural choice.

If you need calculations for each group:

```sql
SELECT department, COUNT(*)
FROM employees
GROUP BY department;
```

is appropriate.

Think of it as:

> **`DISTINCT` → "Give me unique values."**
> **`GROUP BY` → "Give me one group per value so I can calculate something for each group."**
> **`ORDER BY` → "Now arrange the result in a particular order."**

### Interview Takeaway

Remember the three words:

**`ORDER BY` = Sort**
**`GROUP BY` = Group + Aggregate**
**`DISTINCT` = Remove duplicate**

## Answer

These logical operators combine or negate conditions in `WHERE` clauses.

- `AND` requires all conditions to be true.
- `OR` allows any condition to be true.
- `NOT` reverses a condition.

```sql
SELECT *
FROM employees
WHERE department = 'Sales' AND salary > 50000;
```

### Interview takeaway

These operators shape the logic behind filtering. Correct precedence and parentheses are important in complex queries.
