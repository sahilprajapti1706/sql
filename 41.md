## 41. Explain ACID properties

### Answer

**ACID** describes four important properties that make database transactions **reliable and safe**:

* **A — Atomicity**
* **C — Consistency**
* **I — Isolation**
* **D — Durability**

A simple way to remember them:

> **Atomicity → All or nothing**
> **Consistency → Valid state to valid state**
> **Isolation → Concurrent transactions don't improperly interfere**
> **Durability → Committed data stays saved**

---

## 1. Atomicity

**Atomicity means a transaction is treated as one indivisible unit.**

Either all required operations succeed, or the transaction's changes are rolled back.

### Example

Suppose ₹1,000 is transferred from Account A to Account B:

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 1000
WHERE id = 1;

UPDATE accounts
SET balance = balance + 1000
WHERE id = 2;

COMMIT;
```

If the second operation fails, we can roll back:

```sql
ROLLBACK;
```

We don't want this state:

```text
Account A → -₹1,000
Account B → No change
```

Instead, the transaction should leave the database as if the incomplete transfer did not happen.

**Remember:**

> **Atomicity = All or nothing.**

---

## 2. Consistency

**Consistency means a successfully completed transaction takes the database from one valid state to another valid state**, preserving database constraints and defined business invariants.

For example:

```sql
CREATE TABLE accounts (
    id INT PRIMARY KEY,
    balance NUMERIC CHECK (balance >= 0)
);
```

The database should not successfully commit a transaction that violates the `balance >= 0` constraint.

Other examples include:

* Primary-key uniqueness must be maintained.
* Foreign-key relationships must remain valid.
* `NOT NULL` constraints must not be violated.
* `CHECK` constraints must remain satisfied.

**Remember:**

> **Consistency = Database rules remain valid.**

---

## 3. Isolation

**Isolation controls how concurrent transactions interact with each other.**

Imagine two users trying to modify the same account at approximately the same time:

```text
Transaction A
     ↓
Read balance
     ↓
Update balance

Transaction B
     ↓
Read balance
     ↓
Update balance
```

Without appropriate concurrency control, their operations could interfere and produce incorrect results.

Database systems provide **isolation levels** that determine what one transaction can see from other concurrent transactions.

Common isolation levels include:

| Isolation Level  | General idea                                                              |
| ---------------- | ------------------------------------------------------------------------- |
| Read Uncommitted | Allows the weakest visibility guarantees                                  |
| Read Committed   | Reads only committed data                                                 |
| Repeatable Read  | Stronger consistency for repeated reads                                   |
| Serializable     | Strongest standard isolation; transactions behave as if executed serially |

The exact behavior varies by database system.

**Remember:**

> **Isolation = Concurrent transactions should not improperly interfere.**

---

## 4. Durability

**Durability means that once a transaction is successfully committed, its changes should survive failures such as a database restart or crash.**

For example:

```sql
COMMIT;
```

After a successful commit:

```text
Transaction
     ↓
   COMMIT
     ↓
Data is durable
```

Database systems use mechanisms such as **transaction logs** and durable storage to provide this guarantee.

**Remember:**

> **Durability = Committed changes persist.**

---

## ACID in One Example

Consider an online payment:

```text
1. Deduct money from customer
2. Create payment record
3. Update order status
```

These operations can be handled as one transaction.

| Property              | What it means here                                               |
| --------------------- | ---------------------------------------------------------------- |
| **Atomicity**   | All required payment changes succeed together or are rolled back |
| **Consistency** | Database constraints and business invariants remain valid        |
| **Isolation**   | Concurrent transactions don't incorrectly interfere              |
| **Durability**  | Once committed, the payment changes persist                      |

### Interview Takeaway

A good interview answer is:

> **ACID properties make database transactions reliable. Atomicity ensures all-or-nothing execution, Consistency preserves database rules and invariants, Isolation controls interaction between concurrent transactions, and Durability ensures committed changes persist even after failure**
