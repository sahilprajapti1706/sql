
## 49. What is a query execution plan?

### Answer

A **query execution plan** is the plan chosen by the database for **how it will actually execute a SQL query**.

When you write:

```sql
SELECT *
FROM orders
WHERE user_id = 101;
```

you describe **what data you want**, but you don't tell the database exactly how to find it.

The database optimizer decides things such as:

* Should it scan the entire table?
* Should it use an index?
* Which index should it use?
* Which table should be accessed first in a JOIN?
* How should rows be filtered and sorted?
* Which JOIN algorithm should be used?

The resulting strategy is called the **execution plan**.

---

### Simple Example

Suppose `orders` contains **10 million rows**.

You run:

```sql
SELECT *
FROM orders
WHERE user_id = 101;
```

Without a useful index, the database might choose:

```text
Sequential Scan
     ↓
Read many/all rows
     ↓
Check user_id = 101
```

With an appropriate index:

```sql
CREATE INDEX idx_orders_user_id
ON orders(user_id);
```

the plan might instead use:

```text
Index Scan
     ↓
Find user_id = 101 in index
     ↓
Fetch matching rows
```

The second approach may be much faster, depending on the data and query.

---

### How do you see the execution plan?

In PostgreSQL, you can use:

```sql
EXPLAIN
SELECT *
FROM orders
WHERE user_id = 101;
```

This shows the **estimated** execution plan.

For actual execution information:

```sql
EXPLAIN ANALYZE
SELECT *
FROM orders
WHERE user_id = 101;
```

`EXPLAIN ANALYZE` actually runs the query and reports information such as:

```text
Seq Scan
Index Scan
Nested Loop
Hash Join
Sort
Aggregate
```

along with estimated and actual row counts and execution timing.

---

### Estimated vs Actual Plan

This distinction is important in interviews.

**`EXPLAIN`**

```text
Shows what the optimizer expects to happen.
```

**`EXPLAIN ANALYZE`**

```text
Runs the query and shows what actually happened.
```

For example, the optimizer might estimate:

```text
rows=100
```

but the query actually returns:

```text
actual rows=50,000
```

A large difference can indicate that the optimizer's statistics don't accurately represent the data, which can contribute to a poor plan.

---

### Common Execution Plan Operations

| Operation       | Meaning                                                  |
| --------------- | -------------------------------------------------------- |
| Sequential Scan | Reads table rows sequentially                            |
| Index Scan      | Uses an index to locate rows                             |
| Index Only Scan | Gets required data directly from the index when possible |
| Nested Loop     | Repeatedly searches one side for each row from another   |
| Hash Join       | Builds a hash structure to join rows                     |
| Merge Join      | Joins sorted inputs                                      |
| Sort            | Sorts rows                                               |
| Aggregate       | Performs operations such as`SUM()` or `COUNT()`      |

You don't need to memorize every operation initially. The important idea is to understand **why the database chose a particular operation and whether it is efficient for the workload**.

---

### Why is an Execution Plan Important?

It helps you diagnose slow queries.

For example:

```text
Slow query
    ↓
EXPLAIN ANALYZE
    ↓
Find expensive operation
    ↓
Check indexes / JOIN / filtering / sorting
    ↓
Optimize
    ↓
EXPLAIN ANALYZE again
```

For example, if a query expected to use an index but is performing a sequential scan over millions of rows, you can investigate whether:

* the appropriate index exists
* the index matches the query
* the condition is selective enough
* statistics are up to date
* the query itself can be rewritten

### Important Interview Point

**An execution plan is not necessarily the same thing as the SQL query's logical order.**

SQL tells the database **what result you want**. The optimizer chooses an efficient **physical execution strategy** to produce that result.

### Interview Takeaway

> **A query execution plan is the database optimizer's strategy for executing a SQL query. It shows operations such as scans, index usage, joins, sorting, and aggregation. Tools like `EXPLAIN` and `EXPLAIN ANALYZE` help developers understand and optimize query performance.**
