## 9. What is the difference between WHERE and HAVING?

### Answer

Both `WHERE` and `HAVING` are used to **filter data**, but they operate at different stages of a SQL query:

* **`WHERE` filters individual rows before grouping/aggregation.**
* **`HAVING` filters groups after `GROUP BY` and aggregation.**

### Simple Example

Suppose we have an `orders` table:

| id | customer_id | amount |
| -: | ----------: | -----: |
|  1 |         101 |    500 |
|  2 |         101 |    700 |
|  3 |         102 |    300 |
|  4 |         102 |    900 |
|  5 |         103 |    200 |

#### Using `WHERE`

```sql
SELECT *
FROM orders
WHERE amount > 500;
```

`WHERE` checks **each row individually** and keeps only orders where `amount > 500`.

Result:

| id | customer_id | amount |
| -: | ----------: | -----: |
|  2 |         101 |    700 |
|  4 |         102 |    900 |

---

#### Using `HAVING`

Suppose we want customers whose **total order amount is greater than 1000**:

```sql
SELECT customer_id, SUM(amount) AS total_amount
FROM orders
GROUP BY customer_id
HAVING SUM(amount) > 1000;
```

First, SQL groups the orders:

| customer_id | SUM(amount) |
| ----------: | ----------: |
|         101 |        1200 |
|         102 |        1200 |
|         103 |         200 |

Then `HAVING` filters those **groups**:

| customer_id | total_amount |
| ----------: | -----------: |
|         101 |         1200 |
|         102 |         1200 |

### Key Difference

| `WHERE`                                                    | `HAVING`                                                                      |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| Filters rows                                                 | Filters groups                                                                  |
| Applied before`GROUP BY`                                   | Applied after`GROUP BY`                                                       |
| Normally used for individual row conditions                  | Commonly used with aggregate conditions                                         |
| Cannot normally use aggregate results like`SUM()` directly | Can filter using`SUM()`, `COUNT()`, `AVG()`, etc.                         |
| Can be used without`GROUP BY`                              | Commonly used with`GROUP BY`, but can also be used without it in some queries |

### Query Execution Idea

A simplified logical order is:

```text
FROM
  ↓
WHERE
  ↓
GROUP BY
  ↓
HAVING
  ↓
SELECT
  ↓
ORDER BY
```

So:

```sql
SELECT customer_id, COUNT(*) AS orders
FROM orders
WHERE amount > 500
GROUP BY customer_id
HAVING COUNT(*) >= 2;
```

means:

1. Get orders.
2. `WHERE` removes orders with `amount <= 500`.
3. Group the remaining orders by `customer_id`.
4. `HAVING` keeps only customers with at least 2 remaining orders.
5. `SELECT` produces the final output.

### Important Interview Point

A common mistake is trying to use `WHERE` for an aggregate condition:

```sql
-- ❌ Incorrect
SELECT customer_id, SUM(amount)
FROM orders
GROUP BY customer_id
WHERE SUM(amount) > 1000;
```

Use `HAVING` instead:

```sql
-- ✅ Correct
SELECT customer_id, SUM(amount) AS total_amount
FROM orders
GROUP BY customer_id
HAVING SUM(amount) > 1000;
```

But if the condition applies to **individual rows**, use `WHERE`:

```sql
SELECT customer_id, SUM(amount) AS total_amount
FROM orders
WHERE amount > 500
GROUP BY customer_id;
```

Here, the difference is important:

* `WHERE amount > 500` → only orders above 500 participate in the sum.
* `HAVING SUM(amount) > 500` → all orders participate in the sum, and then groups whose total exceeds 500 are retained.

### Interview Takeaway

> **`WHERE` filters rows before grouping, while `HAVING` filters groups after grouping and aggregation.**

A useful memory trick:

**WHERE → individual rows**
**HAVING → grouped/aggregated result**

## Answer

These operators help filter data more efficiently.

- `IN` checks whether a value matches one of many values.
- `BETWEEN` checks whether a value falls inside a range.
- `IS NULL` checks for missing values.

```sql
SELECT *
FROM orders
WHERE status IN ('paid', 'shipped');

SELECT *
FROM products
WHERE price BETWEEN 100 AND 500;

SELECT *
FROM users
WHERE last_login IS NULL;
```

### Interview takeaway

Use these operators to write readable conditions and handle missing data correctly.
