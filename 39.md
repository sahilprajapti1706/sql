
## 39. What is the difference between DELETE, TRUNCATE, and DROP?

### Answer

All three can remove data, but they operate at different levels.

| Command      | Removes rows? | Removes table structure? | `WHERE` allowed? | Typical use             |
| ------------ | ------------- | ------------------------ | ------------------ | ----------------------- |
| `DELETE`   | Yes           | No                       | Yes                | Remove specific rows    |
| `TRUNCATE` | Yes, all rows | No                       | No                 | Quickly empty a table   |
| `DROP`     | Yes           | **Yes**            | No                 | Remove the table itself |

---

## 1. DELETE

`DELETE` removes rows from a table.

```sql
DELETE FROM employees
WHERE department = 'HR';
```

Only HR employees are deleted.

You can also delete all rows:

```sql
DELETE FROM employees;
```

But the **table itself remains**.

### Key points

* Supports `WHERE`.
* Can delete specific rows.
* The table structure remains.
* Foreign-key relationships and constraints remain.
* Row-level triggers may fire, depending on the database.
* In transactional databases such as PostgreSQL, `DELETE` can be rolled back if performed inside a transaction and not committed.

---

## 2. TRUNCATE

`TRUNCATE` removes **all rows** from a table while keeping the table structure.

```sql
TRUNCATE TABLE employees;
```

After this:

```text
employees table → still exists
employees rows  → removed
```

Unlike `DELETE`, you cannot use a normal `WHERE` condition:

```sql
-- Invalid
TRUNCATE TABLE employees
WHERE department = 'HR';
```

### Why use TRUNCATE?

It is designed for quickly removing all rows from a table and generally has less row-by-row overhead than `DELETE`.

For example, you might use it to clear a temporary/staging table before loading fresh data.

### PostgreSQL example

PostgreSQL also supports:

```sql
TRUNCATE TABLE employees
RESTART IDENTITY;
```

This additionally resets identity sequences associated with the table.

`TRUNCATE` behavior around transactions and foreign-key dependencies is database-specific, so exact behavior should be checked for the RDBMS you're using.

---

## 3. DROP

`DROP` removes the **database object itself**.

```sql
DROP TABLE employees;
```

After this:

```text
employees table → does not exist
employees rows  → gone
table structure → gone
```

You would need to recreate the table if you want it again:

```sql
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    salary NUMERIC
);
```

`DROP` is therefore much more destructive than simply deleting the table's data.

---

## 4. Simple Mental Model

Think of a table as a **box containing data**:

```text
DELETE
→ Remove selected items from the box.

TRUNCATE
→ Empty the entire box.

DROP
→ Throw away the box itself.
```

---

## 5. Important Interview Difference

Consider:

```sql
DELETE FROM employees WHERE id = 10;
```

Only employee `10` is removed.

```sql
TRUNCATE TABLE employees;
```

All employees are removed, but `employees` still exists.

```sql
DROP TABLE employees;
```

The entire `employees` table is removed.

---

### Interview Takeaway

The easiest way to remember:

> **DELETE = remove rows**
> **TRUNCATE = empty the table**
> **DROP = remove the table**

And remember the most important distinction:

**`DELETE` can filter rows with `WHERE`; `TRUNCATE` and `DROP` cannot.**
