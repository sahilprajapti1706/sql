## 37. How would you calculate running totals or moving averages?

### Answer

Both **running totals** and **moving averages** are common use cases for **window functions**.

The key idea is:

> **Use `ORDER BY` to define the sequence, and use a window frame to define which rows are included in the calculation.**

---

## 1. Running Total

A **running total** is the cumulative sum of a value up to the current row.

Suppose we have daily sales:

| sale_date  | amount |
| ---------- | -----: |
| 2026-01-01 |    100 |
| 2026-01-02 |    200 |
| 2026-01-03 |    150 |
| 2026-01-04 |    300 |

We can calculate the running total using:

```sql
SELECT
    sale_date,
    amount,
    SUM(amount) OVER (
        ORDER BY sale_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total
FROM sales
ORDER BY sale_date;
```

Result:

| sale_date  | amount | running_total |
| ---------- | -----: | ------------: |
| 2026-01-01 |    100 |           100 |
| 2026-01-02 |    200 |           300 |
| 2026-01-03 |    150 |           450 |
| 2026-01-04 |    300 |           750 |

### How it works

For each row:

```text
Row 1 → 100
Row 2 → 100 + 200 = 300
Row 3 → 100 + 200 + 150 = 450
Row 4 → 100 + 200 + 150 + 300 = 750
```

The important part is:

```sql
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

It means:

> Start from the first row and include everything up to the current row.

For this common running-total pattern, many databases also allow the shorter form:

```sql
SUM(amount) OVER (
    ORDER BY sale_date
)
```

However, explicitly specifying the frame can make the intended behavior clearer, especially when dealing with duplicate ordering values.

---

## 2. Running Total Within Each Group

You can combine `PARTITION BY` with the running total.

For example, calculate the running sales total **for each product**:

```sql
SELECT
    product_id,
    sale_date,
    amount,
    SUM(amount) OVER (
        PARTITION BY product_id
        ORDER BY sale_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total
FROM sales;
```

Here:

* `PARTITION BY product_id` → restart the total for each product.
* `ORDER BY sale_date` → calculate it chronologically.

---

# 3. Moving Average

A **moving average** calculates the average over a fixed number of recent rows.

For example, a **3-day moving average**:

```sql
SELECT
    sale_date,
    amount,
    AVG(amount) OVER (
        ORDER BY sale_date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS moving_avg
FROM sales
ORDER BY sale_date;
```

For:

| sale_date | amount |
| --------- | -----: |
| Jan 1     |    100 |
| Jan 2     |    200 |
| Jan 3     |    150 |
| Jan 4     |    300 |

The result is approximately:

| sale_date | amount | 3-row moving average |
| --------- | -----: | -------------------: |
| Jan 1     |    100 |               100.00 |
| Jan 2     |    200 |               150.00 |
| Jan 3     |    150 |               150.00 |
| Jan 4     |    300 |               216.67 |

For Jan 4:

```text
(200 + 150 + 300) / 3
= 216.67
```

The frame:

```sql
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
```

means:

> Include the current row and the previous 2 rows.

---

## 4. Understanding the Window Frame

This is an important interview concept.

```sql
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
```

means:

```text
previous 2 rows
       ↓
[Row -2] [Row -1] [Current Row]
                     ↑
                  current
```

Similarly:

```sql
ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
```

can be used for a **7-row moving average**.

---

## 5. Running Total vs Moving Average

| Requirement          | Window function                                               |
| -------------------- | ------------------------------------------------------------- |
| Running total        | `SUM() OVER (...)`                                          |
| Running average      | `AVG() OVER (...)`                                          |
| 3-row moving average | `AVG() OVER (... ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)` |
| 7-row moving average | `AVG() OVER (... ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` |

### Important distinction

**Running total:**

```text
100
100 + 200
100 + 200 + 150
100 + 200 + 150 + 300
```

The window keeps growing.

**Moving average:**

```text
100
100, 200
100, 200, 150
200, 150, 300
```

The window moves forward and generally stays fixed in size after the initial rows.

---

## Practical Example

For an e-commerce application, you might calculate a **7-day moving average of daily orders**:

```sql
SELECT
    order_date,
    orders_count,
    AVG(orders_count) OVER (
        ORDER BY order_date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS seven_day_avg
FROM daily_orders
ORDER BY order_date;
```

This can help smooth daily fluctuations and make trends easier to analyze.

### Interview Takeaway

Remember this pattern:

**Running total:**

```sql
SUM(value) OVER (
    ORDER BY date
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```

**Moving average:**

```sql
AVG(value) OVER (
    ORDER BY date
    ROWS BETWEEN N-1 PRECEDING AND CURRENT ROW
)
```

The key interview concept is the **window frame**:

> `ORDER BY` determines the sequence, while `ROWS BETWEEN ...` determines which rows participate in the calculatio
