## 17. Explain INNER JOIN.

### Answer

An **`INNER JOIN`** returns only the rows where there is a **matching value in both tables** according to the JOIN condition.

In simple terms:

> **INNER JOIN = Give me only the records that exist on both sides of the relationship.**

---

## Example

Suppose we have two tables.

### `users`

| id | name  |
| -: | ----- |
|  1 | Sahil |
|  2 | Rahul |
|  3 | Priya |
|  4 | Ankit |

### `orders`

|  id | user_id | amount |
| --: | ------: | -----: |
| 101 |       1 |    500 |
| 102 |       2 |    800 |
| 103 |       1 |   1200 |
| 104 |       5 |    300 |

Here:

```text
users.id  ←→  orders.user_id
```

Now:

```sql
SELECT
    users.name,
    orders.amount
FROM users
INNER JOIN orders
    ON users.id = orders.user_id;
```

### Result

| name  | amount |
| ----- | -----: |
| Sahil |    500 |
| Rahul |    800 |
| Sahil |   1200 |

Notice:

* **Priya** is not returned because she has no matching order.
* **Ankit** is not returned because he has no matching order.
* The order with `user_id = 5` is not returned because there is no user with `id = 5`.

So only matching records are included.

---

# How INNER JOIN Works

Conceptually:

```text
users                     orders

id  name                  user_id  amount
1   Sahil  ────────────→  1        500
2   Rahul  ────────────→  2        800
3   Priya
4   Ankit                 1        1200

                          5        300
```

The condition:

```sql
ON users.id = orders.user_id
```

matches:

```text
users.id = 1  → orders.user_id = 1
users.id = 2  → orders.user_id = 2
users.id = 1  → orders.user_id = 1
```

Only those matches appear in the result.

---

## Basic Syntax

```sql
SELECT columns
FROM table1
INNER JOIN table2
    ON table1.column = table2.column;
```

For example:

```sql
SELECT
    u.name,
    o.amount
FROM users AS u
INNER JOIN orders AS o
    ON u.id = o.user_id;
```

Using aliases like `u` and `o` makes queries easier to read, especially when joining multiple tables.

---

# INNER JOIN Can Produce Multiple Rows

An important point is that a JOIN doesn't necessarily produce one result row per user.

If Sahil has three orders:

```text
Sahil → Order 1
Sahil → Order 2
Sahil → Order 3
```

then an INNER JOIN produces **three rows for Sahil**.

This is because the JOIN operates on matching **row combinations**, not just unique entities.

This is especially important when working with **one-to-many relationships**.

---

# INNER JOIN with Multiple Tables

You can join more than two tables.

Suppose:

```text
users
listings
applications
```

and `applications` contains:

```text
user_id
listing_id
status
```

You can write:

```sql
SELECT
    u.name AS investor,
    l.title AS listing,
    a.status
FROM applications AS a
INNER JOIN users AS u
    ON a.user_id = u.id
INNER JOIN listings AS l
    ON a.listing_id = l.id;
```

This returns applications only when:

1. The application has a matching user.
2. The application has a matching listing.

---

# INNER JOIN vs LEFT JOIN

This is a very common interview question.

### INNER JOIN

```sql
FROM users u
INNER JOIN orders o
    ON u.id = o.user_id
```

Returns:

> Users **who have matching orders**.

### LEFT JOIN

```sql
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id
```

Returns:

> **All users**, whether or not they have orders.

If you need to find users who **have no orders**, a `LEFT JOIN` is typically used:

```sql
SELECT u.name
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id
WHERE o.id IS NULL;
```

---

## INNER JOIN and Foreign Keys

A common relationship is:

```text
users
  id (PRIMARY KEY)
      ↑
      │
orders
  user_id (FOREIGN KEY)
```

Then:

```sql
ON users.id = orders.user_id
```

connects the two tables.

However, remember:

> An `INNER JOIN` does **not require** a foreign key constraint to exist.

The JOIN simply uses the condition you provide. A foreign key is a database constraint that helps maintain referential integrity.

---

## Common Mistake: Incorrect JOIN Condition

Suppose you have:

```sql
SELECT *
FROM users u
INNER JOIN orders o
    ON u.id = o.id;
```

This might be syntactically valid, but it may be **logically wrong**.

If `orders.user_id` stores the user's ID, the correct relationship is:

```sql
ON u.id = o.user_id
```

The important thing isn't just knowing JOIN syntax; you need to understand **which columns actually represent the relationship**.

---

## Interview Takeaway

> **INNER JOIN returns only the rows that have matching records in both tables based on the specified JOIN condition.**

Remember:

```text
INNER JOIN
    ↓
Match rows
    ↓
Keep only matches
    ↓
Return combined data
```

For example:

```sql
SELECT u.name, o.amount
FROM users u
INNER JOIN orders o
    ON u.id = o.user_id;
```

means:

> **"Give me users and their orders, but only where a matching order exists**

## Answer

An `INNER JOIN` returns only rows that have matches in both tables. A `LEFT JOIN` returns all rows from the left table and matching rows from the right table, filling missing matches with `NULL`.

```sql
SELECT u.name, o.amount
FROM users u
LEFT JOIN orders o
  ON u.id = o.user_id;
```

### Interview takeaway

Use `LEFT JOIN` when you want to preserve all records from the primary table while optionally attaching related data.
