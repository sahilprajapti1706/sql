## 3. What are tables, rows, columns, and records?

### Answer

In a relational database, data is organized into **tables**, and tables are made up of **rows and columns**.

Consider a `users` table:

```text id="v3y0x7"
users
+----+----------+---------------------+-----+
| id | name     | email               | age |
+----+----------+---------------------+-----+
| 1  | Sahil    | sahil@example.com    | 21  |
| 2  | Rahul    | rahul@example.com    | 22  |
| 3  | Priya    | priya@example.com    | 20  |
+----+----------+---------------------+-----+
```

### 1. Table

A **table** is a structured collection of related data organized into **rows and columns**.

For example:

```text id="x4f8jm"
users
orders
products
```

could be different tables in an e-commerce database.

Think of a table as similar to a spreadsheet, although a database table also has rules such as data types, constraints, keys, and relationships.

---

### 2. Column

A **column** represents a particular **attribute or property** of the data.

In the example:

```text id="w3n7sa"
id
name
email
age
```

are columns.

Each column generally has a defined **data type**.

For example:

```sql id="q1p3fz"
CREATE TABLE users (
    id INTEGER,
    name VARCHAR(100),
    email VARCHAR(255),
    age INTEGER
);
```

Here:

* `id` → integer
* `name` → text/string
* `email` → text/string
* `age` → integer

A column describes **what type of information is stored** for each row.

---

### 3. Row

A **row** represents one individual entry in a table.

For example:

```text id="g5k2rp"
| 1 | Sahil | sahil@example.com | 21 |
```

is one row.

It represents one particular user and contains values for the columns defined by the table.

---

### 4. Record

In a relational database, **record** is commonly used as another term for a **row**.

For example:

```text id="0p8x4a"
| 1 | Sahil | sahil@example.com | 21 |
```

is a record containing information about one user.

So, for basic interview purposes:

> **Row ≈ Record**

The terms are often used interchangeably, although "row" is the more formal relational-database terminology.

---

## How they relate to each other

```text id="f0m8ny"
Database
   │
   └── Table: users
          │
          ├── Columns
          │     ├── id
          │     ├── name
          │     ├── email
          │     └── age
          │
          ├── Row / Record 1
          │     └── 1, Sahil, sahil@example.com, 21
          │
          ├── Row / Record 2
          │     └── 2, Rahul, rahul@example.com, 22
          │
          └── Row / Record 3
                └── 3, Priya, priya@example.com, 20
```

### A simple way to remember

Think of an Excel-like structure:

| Database concept | Think of it as                |
| ---------------- | ----------------------------- |
| **Table**        | A complete sheet              |
| **Column**       | A field/property              |
| **Row**          | One entry                     |
| **Record**       | Another common name for a row |

---

## Practical SQL Example

Suppose we want to retrieve the `name` and `email` columns:

```sql id="r7k1vd"
SELECT name, email
FROM users;
```

The database might return:

```text id="h6j2pq"
name    | email
--------|-------------------
Sahil   | sahil@example.com
Rahul   | rahul@example.com
Priya   | priya@example.com
```

If we want one particular record:

```sql id="m2z8wc"
SELECT *
FROM users
WHERE id = 1;
```

Result:

```text id="c5v9ra"
1 | Sahil | sahil@example.com | 21
```

---

## Why this matters

Understanding these four terms is fundamental because almost every relational database operation works with them.

For example:

```sql id="p8q4de"
UPDATE users
SET age = 22
WHERE id = 1;
```

Here:

* `users` → **table**
* `age` → **column**
* `id = 1` identifies a particular **row/record**
* `22` → new value stored in that column for that record

### Interview Takeaway

> **A table stores related data, columns define the attributes of that data, and rows represent individual entries. A record is commonly another name for a row.**

The easiest mental model is:

**Table → Columns describe the data → Rows/records contain individual data entries.**
