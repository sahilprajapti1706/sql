## 8. Explain SELECT, FROM, and WHERE

### Answer

`SELECT`, `FROM`, and `WHERE` are fundamental SQL clauses used to **retrieve specific data from a table**.

The basic structure is:

```sql
SELECT columns
FROM table
WHERE condition;
```

A simple way to remember:

```text
SELECT → What do I want?
FROM   → Where is it?
WHERE  → Which rows do I want?
```

Consider this `employees` table:

```text
employees
+----+--------+------------+--------+
| id | name   | department | salary |
+----+--------+------------+--------+
| 1  | Sahil  | IT         | 30000  |
| 2  | Rahul  | HR         | 35000  |
| 3  | Priya  | IT         | 40000  |
| 4  | Amit   | Sales      | 32000  |
+----+--------+------------+--------+
```

---

## 1. SELECT

`SELECT` specifies **which columns or expressions you want in the result**.

### Select specific columns

```sql
SELECT name, salary
FROM employees;
```

Result:

```text
name   | salary
-------|-------
Sahil  | 30000
Rahul  | 35000
Priya  | 40000
Amit   | 32000
```

Here:

```text
SELECT name, salary
```

means:

> Return the `name` and `salary` columns.

### Select all columns

```sql
SELECT *
FROM employees;
```

`*` means all columns.

However, in production queries, explicitly selecting the required columns is often preferable because it makes the query clearer and avoids retrieving unnecessary data.

---

# 2. FROM

`FROM` specifies **the table or data source from which the data should be retrieved**.

```sql
SELECT name
FROM employees;
```

Here:

```text
SELECT name → What?
FROM employees → From where?
```

The database looks at the `employees` table and returns its `name` values.

`FROM` becomes especially important when working with multiple tables:

```sql
SELECT employees.name, departments.name
FROM employees
JOIN departments
    ON employees.department_id = departments.id;
```

Here, `FROM` establishes the starting table and the `JOIN` adds another related table.

---

# 3. WHERE

`WHERE` filters **rows** based on a condition.

For example:

```sql
SELECT name, salary
FROM employees
WHERE department = 'IT';
```

Result:

```text
name   | salary
-------|-------
Sahil  | 30000
Priya  | 40000
```

The database considers each row and keeps only those where:

```text
department = 'IT'
```

is true.

### Using comparison operators

```sql
SELECT name, salary
FROM employees
WHERE salary > 35000;
```

Result:

```text
name  | salary
------|-------
Priya | 40000
```

Common operators include:

```text
=       Equal
<>      Not equal
>       Greater than
<       Less than
>=      Greater than or equal
<=      Less than or equal
```

---

# Combining SELECT, FROM, and WHERE

A typical query looks like:

```sql
SELECT name, salary
FROM employees
WHERE department = 'IT'
  AND salary >= 35000;
```

The conceptual process is:

```text
employees
    ↓
FROM employees
    ↓
Filter rows using WHERE
    ↓
department = 'IT'
AND salary >= 35000
    ↓
Select requested columns
    ↓
SELECT name, salary
```

Result:

```text
name  | salary
------|-------
Priya | 40000
```

---

## WHERE can use multiple conditions

### AND

Both conditions must be true:

```sql
SELECT *
FROM employees
WHERE department = 'IT'
  AND salary > 35000;
```

### OR

At least one condition must be true:

```sql
SELECT *
FROM employees
WHERE department = 'IT'
   OR department = 'HR';
```

### NOT

Negates a condition:

```sql
SELECT *
FROM employees
WHERE NOT department = 'IT';
```

---

## WHERE with NULL

A common SQL mistake is:

```sql
WHERE manager_id = NULL
```

This does **not** correctly test for `NULL`.

Use:

```sql
WHERE manager_id IS NULL;
```

or:

```sql
WHERE manager_id IS NOT NULL;
```

This is because `NULL` represents a missing/unknown value and follows SQL's three-valued logic rather than behaving like an ordinary value.

---

## WHERE vs SELECT

A useful distinction:

```sql
SELECT name
FROM employees
WHERE salary > 35000;
```

* `SELECT name` → determines **which columns appear in the result**.
* `WHERE salary > 35000` → determines **which rows appear in the result**.

So:

> **SELECT filters columns; WHERE filters rows.**

More precisely, `SELECT` defines the result expressions/columns, while `WHERE` filters the input rows based on a condition.

---

## Example from a Real Application

Suppose an e-commerce application needs all active users:

```sql
SELECT id, name, email
FROM users
WHERE status = 'active';
```

The backend might execute this query when displaying active users in an admin dashboard.

For user-provided values, use **parameterized queries** rather than constructing SQL through string concatenation:

```sql
SELECT id, name, email
FROM users
WHERE status = $1;
```

The actual value is supplied separately by the application. This helps prevent SQL injection.

## Common Mistakes

### 1. Putting the table name in SELECT

Incorrect:

```sql
SELECT employees
FROM name;
```

Correct:

```sql
SELECT name
FROM employees;
```

### 2. Using `=` with NULL

Incorrect:

```sql
WHERE email = NULL;
```

Correct:

```sql
WHERE email IS NULL;
```

### 3. Confusing rows and columns

```sql
SELECT name, email
```

chooses **columns**.

```sql
WHERE department = 'IT'
```

filters **rows**.

### 4. Using `SELECT *` everywhere

`SELECT *` is useful for exploration, but application code often benefits from explicitly selecting the columns it needs.

## Interview Takeaway

Remember:

```text
SELECT → Which columns/expressions?
FROM   → Which table/source?
WHERE  → Which rows?
```

For example:

```sql
SELECT name, salary
FROM employees
WHERE salary > 35000;
```

means:

> **Get the `name` and `salary` columns from the `employees` table, but only for employees whose salary is greater than 35,00**

## Answer

The `LIKE` operator matches patterns in text values. It uses wildcard characters such as `%` for any number of characters and `_` for a single character.

```sql
SELECT *
FROM users
WHERE name LIKE 'S%';
```

This returns names starting with `S`.

### Interview takeaway

`LIKE` is useful for text searching, but it is slower than exact matching for large tables unless indexes or full-text features are used.
