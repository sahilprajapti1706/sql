## 27. What is a CTE?

### Answer

A **CTE (Common Table Expression)** is a **temporary named result set** that you define at the beginning of a SQL query using the `WITH` keyword.

It allows you to break a complex query into **smaller, named, easier-to-understand steps**.

### Basic Syntax

```sql
WITH cte_name AS (
    SELECT ...
)
SELECT ...
FROM cte_name;
```

Think of it as:

```text
WITH
  ↓
Define a temporary result
  ↓
Give it a name
  ↓
Use that name in the main query
```

The CTE exists only for the duration of that SQL statement. It does **not** create a permanent table.

---

## Example

Suppose we want to find employees whose salary is above the **average salary**.

Without a CTE:

```sql
SELECT name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

Using a CTE:

```sql
WITH avg_salary AS (
    SELECT AVG(salary) AS average
    FROM employees
)
SELECT
    e.name,
    e.salary
FROM employees e
CROSS JOIN avg_salary a
WHERE e.salary > a.average;
```

The CTE:

```sql
WITH avg_salary AS (
    SELECT AVG(salary) AS average
    FROM employees
)
```

creates a temporary named result called `avg_salary`.

The main query can then use it.

---

## Why use a CTE?

The biggest benefit is **readability and organization**.

Instead of writing one large complicated query, you can divide it into logical steps.

For example:

```sql
WITH high_value_orders AS (
    SELECT customer_id, amount
    FROM orders
    WHERE amount > 1000
),
customer_totals AS (
    SELECT
        customer_id,
        SUM(amount) AS total_amount
    FROM high_value_orders
    GROUP BY customer_id
)
SELECT *
FROM customer_totals
WHERE total_amount > 5000;
```

Here, the query has two logical stages:

```text
All orders
    ↓
Orders > 1000
    ↓
Group by customer
    ↓
Calculate total
    ↓
Keep totals > 5000
```

This is much easier to understand than putting everything into one deeply nested query.

---

## CTE vs Subquery

A CTE and a subquery can sometimes solve the same problem.

### Subquery

```sql
SELECT name
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

### CTE

```sql
WITH avg_salary AS (
    SELECT AVG(salary) AS average
    FROM employees
)
SELECT e.name
FROM employees e
CROSS JOIN avg_salary a
WHERE e.salary > a.average;
```

The CTE is often easier to read when the query becomes more complex.

### Main difference

| CTE                                          | Subquery                                     |
| -------------------------------------------- | -------------------------------------------- |
| Defined using`WITH`                        | Written inside another query                 |
| Has a name                                   | Usually doesn't have a separate name         |
| Good for breaking complex queries into steps | Good for localized filtering/calculation     |
| Can define multiple CTEs                     | Can have nested subqueries                   |
| Exists only for the current statement        | Exists only as part of the current statement |

## Multiple CTEs

You can define multiple CTEs in one query:

```sql
WITH
recent_orders AS (
    SELECT *
    FROM orders
    WHERE order_date >= CURRENT_DATE - INTERVAL '30 days'
),
customer_totals AS (
    SELECT
        customer_id,
        SUM(amount) AS total
    FROM recent_orders
    GROUP BY customer_id
)
SELECT *
FROM customer_totals
WHERE total > 10000;
```

The second CTE can use the first CTE.

This makes complex analytical queries much easier to structure.

---

## Recursive CTE

CTEs can also be **recursive** using `WITH RECURSIVE`.

They are useful for hierarchical data such as:

* Employee → Manager relationships
* Category → Subcategory trees
* Organization structures
* Graph-like relationships

For example:

```sql
WITH RECURSIVE employee_tree AS (
    SELECT id, name, manager_id
    FROM employees
    WHERE manager_id IS NULL

    UNION ALL

    SELECT e.id, e.name, e.manager_id
    FROM employees e
    JOIN employee_tree et
        ON e.manager_id = et.id
)
SELECT *
FROM employee_tree;
```

The query starts with top-level employees and recursively finds their subordinates.

You don't need recursion for every CTE—the vast majority of CTEs are ordinary, non-recursive CTEs.

---

## Important Performance Point

A CTE is **not automatically a performance optimization**.

Its main benefit is usually **query organization and readability**.

In PostgreSQL, the optimizer can inline many CTEs, while some CTEs may be materialized depending on the query and PostgreSQL version/options.

So don't assume:

> "Using a CTE will make my query faster."

For performance-sensitive queries, inspect the actual execution plan with:

```sql
EXPLAIN ANALYZE
```

### Interview Takeaway

> **A CTE (Common Table Expression) is a temporary named result set defined using `WITH`, mainly used to make complex SQL queries easier to read, structure, and maintain.**

Remember:

```text
CTE = WITH + named temporary result + main query
```

And an important distinction:

**CTE → primarily a way to structure a query**
**Temporary table → actual temporary table that can be used across statements within its scop**

CREATE TABLE orders (
