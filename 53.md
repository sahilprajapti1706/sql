## 53. What are one-to-one, one-to-many, and many-to-many relationships?

### Answer

Relationships describe **how records in one table are related to records in another table**.

The three common types are:

1. **One-to-One (1:1)**
2. **One-to-Many (1:N)**
3. **Many-to-Many (M:N)**

These relationships are usually implemented using **primary keys and foreign keys**.

---

## 1. One-to-One (1:1)

A **one-to-one relationship** means one record in Table A is associated with **at most one** record in Table B, and vice versa.

### Example: User and User Profile

```text
users
+----+--------+
| id | name   |
+----+--------+
| 1  | Rahul  |
| 2  | Amit   |
+----+--------+

user_profiles
+----+----------+-------------+
| id | user_id  | bio         |
+----+----------+-------------+
| 1  | 1        | Developer   |
| 2  | 2        | Designer    |
+----+----------+-------------+
```

Here:

```text
users.id
   ↓
user_profiles.user_id
```

`user_profiles.user_id` should be **UNIQUE** if each user can have only one profile.

```sql
CREATE TABLE user_profiles (
    id BIGINT PRIMARY KEY,
    user_id BIGINT UNIQUE NOT NULL,
    bio TEXT,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

The `UNIQUE` constraint is important because a normal foreign key alone would allow:

```text
user_id = 1
user_id = 1
user_id = 1
```

which would make it one-to-many rather than one-to-one.

### Common examples

* User ↔ Profile
* Employee ↔ Employee ID card
* Person ↔ Passport

---

# 2. One-to-Many (1:N)

A **one-to-many relationship** means:

> One record in Table A can be associated with many records in Table B, while each record in Table B belongs to one record in Table A.

### Example: Customer and Orders

One customer can place many orders:

```text
customers
+----+-------+
| id | name  |
+----+-------+
| 1  | Rahul |
| 2  | Amit  |
+----+-------+

orders
+-----+-------------+--------+
| id  | customer_id | amount |
+-----+-------------+--------+
| 101 | 1           | 500    |
| 102 | 1           | 800    |
| 103 | 2           | 300    |
| 104 | 1           | 200    |
+-----+-------------+--------+
```

Relationship:

```text
Customer 1
   ├── Order 101
   ├── Order 102
   └── Order 104

Customer 2
   └── Order 103
```

The foreign key is on the **many side**:

```sql
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    customer_id BIGINT NOT NULL,
    amount NUMERIC(10,2),

    FOREIGN KEY (customer_id)
        REFERENCES customers(id)
);
```

### Common examples

* Customer → Orders
* Department → Employees
* Brand → Listings
* User → Applications

### Key rule

> **In a one-to-many relationship, the foreign key normally lives on the "many" side.**

---

# 3. Many-to-Many (M:N)

A **many-to-many relationship** means:

* One record in Table A can be related to many records in Table B.
* One record in Table B can also be related to many records in Table A.

### Example: Students and Courses

One student can enroll in multiple courses:

```text
Rahul → SQL
Rahul → Java
```

And one course can have multiple students:

```text
SQL → Rahul
SQL → Amit
SQL → Priya
```

You cannot normally represent this cleanly with just a foreign key in either table.

Instead, we use a **junction table** (also called a bridge/association table).

```text
students
+----+-------+
| id | name  |
+----+-------+
| 1  | Rahul |
| 2  | Amit  |
+----+-------+

courses
+-----+--------+
| id  | name   |
+-----+--------+
| 101 | SQL    |
| 102 | Java   |
+-----+--------+

student_courses
+------------+-----------+
| student_id | course_id |
+------------+-----------+
| 1          | 101       |
| 1          | 102       |
| 2          | 101       |
+------------+-----------+
```

The junction table contains two foreign keys:

```sql
CREATE TABLE student_courses (
    student_id BIGINT NOT NULL,
    course_id BIGINT NOT NULL,

    PRIMARY KEY (student_id, course_id),

    FOREIGN KEY (student_id)
        REFERENCES students(id),

    FOREIGN KEY (course_id)
        REFERENCES courses(id)
);
```

The composite primary key prevents the same student from being enrolled in the same course twice.

---

## Quick Comparison

| Relationship  | Meaning          | Typical Implementation      |
| ------------- | ---------------- | --------------------------- |
| **1:1** | One A ↔ One B   | Foreign key +`UNIQUE`     |
| **1:N** | One A ↔ Many B  | Foreign key on B            |
| **M:N** | Many A ↔ Many B | Junction table with two FKs |

### Visual Memory

```text
1 : 1

User ───────── Profile


1 : N

Customer ──────┬── Order
               ├── Order
               └── Order


M : N

Student ───┬── Student_Course ── Course
Student ───┤
Student ───┘
```

### Important Interview Point

A relationship describes the **business relationship**, while foreign keys enforce the corresponding **referential integrity**.

For example, in:

```text
customers 1 ───── N orders
```

the `orders.customer_id` foreign key ensures that an order references a valid customer, but the relationship's cardinality also depends on constraints such as whether `customer_id` can be `NULL`.

### Interview Takeaway

> **One-to-one means one record relates to one record, one-to-many means one record can relate to many records, and many-to-many means records on both sides can relate to many records.
