
## 47. What is a clustered vs non-clustered index?

### Answer

The main difference is **how the index relates to the table's physical/logical storage of rows**.

> **Clustered index → the table's rows are organized around the index key.**
> **Non-clustered index → the index is a separate structure that points to the table's rows.**

However, the exact implementation is **database-specific**, so the terms should not be treated as identical across PostgreSQL, MySQL, and SQL Server.

---

## 1. Clustered Index

A clustered index determines the organization of the table's data around the indexed key.

For example, imagine employees sorted by `id`:

```text
Clustered index on id

1 → Amit
2 → Rahul
3 → Priya
4 → Neha
5 → Raj
```

The table's data is organized according to that index key.

This can make queries involving the clustered key or ranges of that key efficient.

For example:

```sql
SELECT *
FROM employees
WHERE id BETWEEN 100 AND 200;
```

---

## 2. Non-Clustered Index

A non-clustered index is a **separate index structure** that stores indexed values and references to the corresponding table rows.

Conceptually:

```text
Index
----------------
email              → row reference
amit@example.com   → Row 101
neha@example.com   → Row 205
rahul@example.com  → Row 310
```

The actual table data remains separate.

For example:

```sql
CREATE INDEX idx_users_email
ON users(email);
```

The database can search the index for an email and then access the corresponding row.

---

## 3. Simple Analogy

Think of a physical book.

### Clustered

Imagine the book's pages themselves are arranged according to the indexed information.

```text
Page 1 → IDs 1–10
Page 2 → IDs 11–20
Page 3 → IDs 21–30
```

The data itself follows the organization.

### Non-clustered

Imagine a separate index at the back:

```text
Amit    → Page 10
Rahul   → Page 25
Priya   → Page 42
```

The index tells you where the actual data is located.

---

## 4. Important Difference

| Feature                  | Clustered                        | Non-clustered       |
| ------------------------ | -------------------------------- | ------------------- |
| Data organization        | Organized around index key       | Separate from index |
| Number per table         | Generally limited to one         | Multiple possible   |
| Separate index structure | Depends on DB implementation     | Yes                 |
| Good for range access    | Often                            | Can be              |
| Multiple indexes         | Limited by physical organization | Multiple possible   |

The reason a table generally has only one clustered organization is that the same rows cannot simultaneously be physically organized in multiple different orders.

---

## 5. SQL Server Example

This distinction is especially important in **SQL Server**, where clustered and non-clustered indexes are explicit index types.

For example:

```sql
CREATE CLUSTERED INDEX idx_employees_id
ON employees(id);
```

And:

```sql
CREATE NONCLUSTERED INDEX idx_employees_email
ON employees(email);
```

Here, the table has one clustered organization based on `id`, while it can have multiple non-clustered indexes such as `email`, `department`, etc.

---

## 6. Important PostgreSQL Difference

If you're using **PostgreSQL**, be careful with the terminology.

PostgreSQL does **not** have SQL Server-style clustered indexes where a clustered index permanently determines the table's physical organization.

PostgreSQL has the `CLUSTER` command, which can physically reorder a table according to an index:

```sql
CLUSTER employees USING idx_employees_id;
```

But this is a **one-time/rewrite-style physical reorganization**, not a continuously maintained clustered-index structure like SQL Server's.

PostgreSQL's normal indexes, such as B-tree indexes created with:

```sql
CREATE INDEX idx_users_email
ON users(email);
```

are separate index structures that point to table tuples.

---

## 7. Interview Trap

Don't simply say:

> "Clustered index stores the table physically sorted, while non-clustered stores pointers."

That is a useful **simplified model**, but it isn't universally correct across database systems.

A better interview answer is:

> **A clustered index determines how table data is organized around an index key, while a non-clustered index is a separate structure that provides indexed access to the underlying rows. The exact implementation is database-specific.**

### Interview Takeaway

Remember:

```text
Clustered
→ Data organization follows the index key
→ Generally one clustered organization per table

Non-clustered
→ Separate index structure
→ Can have multiple indexes
→ Points/references to the underlying rows
```

And if the interviewer asks specifically about **PostgreSQL vs SQL Server**, mention that PostgreSQL's `CLUSTER` is not the same concept as SQL Server's continuously maintained clustered index.
