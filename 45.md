## 45. How does an index improve query performance?

### Answer

An index improves query performance by allowing the database to **locate relevant rows without scanning every row in the table**.

The simplest analogy is a **book index**:

* Without an index → scan page by page.
* With an index → look up the topic and jump to the relevant pages.

The same idea applies to database tables.

---

## 1. Without an Index

Suppose we have **1 million users**:

```sql
SELECT *
FROM users
WHERE email = 'sahil@example.com';
```

If there is no suitable index, the database may perform a **sequential/table scan**:

```text
Row 1       → check email
Row 2       → check email
Row 3       → check email
...
Row 1,000,000 → check email
```

This can be expensive for a large table.

---

## 2. With an Index

Create an index:

```sql
CREATE INDEX idx_users_email
ON users(email);
```

The database can now use the index to locate the matching email much more efficiently.

Conceptually:

```text
Query
  ↓
Index
  ↓
Find email
  ↓
Locate matching row
  ↓
Return data
```

Instead of examining every row, the database navigates the index structure to find the relevant key.

---

## 3. Why B-tree Indexes Are Efficient

A common index structure is a **B-tree**.

It keeps indexed values organized so the database can efficiently navigate toward the required value.

For example:

```text
                 50
              /      \
            25        75
           /  \      /  \
         10   40   60   90
```

To find `60`, the database doesn't need to inspect every value:

```text
50
 ↓
75
 ↓
60
```

This gives efficient lookup behavior, commonly described as approximately **O(log n)** for B-tree searches, although real query cost also depends on factors such as caching, selectivity, table layout, and whether the query needs to fetch many table rows.

---

## 4. Indexes Can Help More Than `WHERE`

Indexes aren't only useful for simple lookups.

They can also help suitable queries involving:

### `WHERE`

```sql
SELECT *
FROM users
WHERE email = 'sahil@example.com';
```

### `JOIN`

```sql
SELECT *
FROM orders o
JOIN users u
    ON u.id = o.user_id;
```

An index on `orders(user_id)` can help the database efficiently locate orders for users, depending on the query plan.

### `ORDER BY`

An appropriate index can sometimes allow the database to retrieve rows in the required order without performing a separate sort.

### Range queries

```sql
SELECT *
FROM employees
WHERE salary BETWEEN 50000 AND 80000;
```

B-tree indexes are particularly useful for equality and range conditions on suitable columns.

---

## 5. Index Selectivity Matters

An index is most useful when it can significantly reduce the number of rows that need to be examined.

For example:

```text
email
--------
sahil@example.com
rahul@example.com
priya@example.com
...
```

Email addresses are usually highly selective because a particular email may match only one or very few rows.

But consider:

```text
gender
------
Male
Female
Male
Male
Female
...
```

An index on a low-cardinality column may not provide much benefit for some queries because a large portion of the table may still need to be examined.

The optimizer decides whether using the index is actually cheaper.

---

## 6. Index Doesn't Always Mean Faster

This is an important interview point.

Suppose a table contains only 100 rows.

For:

```sql
SELECT *
FROM users
WHERE status = 'active';
```

if almost every row is active, scanning the table may be cheaper than using an index and then fetching most of the table's rows.

Therefore:

> **The database optimizer chooses whether to use an index based on the estimated cost.**

You can inspect this with:

```sql
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE email = 'sahil@example.com';
```

---

## 7. The Trade-off

Indexes improve many read operations, but they have costs.

```text
                    Index
                      ↓
          ┌───────────┴───────────┐
          ↓                       ↓
      Faster reads           Extra storage
                                  +
                           Slower writes
```

When you:

```sql
INSERT
UPDATE
DELETE
```

the database may also need to maintain the relevant indexes.

Therefore, creating an index on every column is not a good strategy.

---

## Practical Example

Suppose your backend frequently executes:

```sql
SELECT *
FROM listings
WHERE owner_id = $1
ORDER BY created_at DESC;
```

A potentially useful index could be:

```sql
CREATE INDEX idx_listings_owner_created
ON listings(owner_id, created_at DESC);
```

This index may help the database efficiently locate an owner's listings and retrieve them in the desired order.

Whether this is actually beneficial should be verified using the query plan and real workload.

### Interview Takeaway

Remember:

> **An index improves performance by providing an efficient lookup structure so the database can avoid examining every table row.**

The key points are:

1. **Without an index** → database may scan many/all rows.
2. **With a suitable index** → database can locate relevant rows more efficiently.

4. **Indexes can help `WHERE`, `JOIN`, and `ORDER BY` queries**, depending on the query.
5. **Indexes have a cost** → storage + additional write/maintenance overhead.
