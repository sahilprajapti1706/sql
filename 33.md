## 33. Explain RANK() and DENSE_RANK().

### Answer

`RANK()` and `DENSE_RANK()` are **SQL window functions** used to assign rankings to rows based on an ordering.

The key difference appears when **two or more rows have the same value**.

---

### 1. `RANK()`

`RANK()` gives the **same rank to tied rows**, but leaves gaps in the ranking after the tie.

**Syntax:**

```sql
RANK() OVER (
    [PARTITION BY column]
    ORDER BY column DESC
)
```

Example:

```sql
SELECT
    name,
    salary,
    RANK() OVER (ORDER BY salary DESC) AS salary_rank
FROM employees;
```

Suppose the data is:

| name  | salary |
| ----- | -----: |
| Amit  | 100000 |
| Rahul |  90000 |
| Priya |  90000 |
| Neha  |  80000 |

Result:

| name  | salary | salary_rank |
| ----- | -----: | ----------: |
| Amit  | 100000 |           1 |
| Rahul |  90000 |           2 |
| Priya |  90000 |           2 |
| Neha  |  80000 |           4 |

Notice that **rank 3 is skipped** because two employees occupy rank 2.

So:

**`RANK()` → ties get the same rank + gaps are created.**

---

### 2. `DENSE_RANK()`

`DENSE_RANK()` also gives the **same rank to tied rows**, but it **does not leave gaps**.

```sql
SELECT
    name,
    salary,
    DENSE_RANK() OVER (ORDER BY salary DESC) AS salary_rank
FROM employees;
```

Result:

| name  | salary | salary_rank |
| ----- | -----: | ----------: |
| Amit  | 100000 |           1 |
| Rahul |  90000 |           2 |
| Priya |  90000 |           2 |
| Neha  |  80000 |           3 |

Here, after rank 2, the next distinct salary gets rank 3.

So:

**`DENSE_RANK()` → ties get the same rank + no gaps.**

---

### 3. Main Difference

| Function         | Ties              | Gaps after ties? |
| ---------------- | ----------------- | ---------------- |
| `ROW_NUMBER()` | Different numbers | No               |
| `RANK()`       | Same rank         | **Yes**    |
| `DENSE_RANK()` | Same rank         | **No**     |

For example, with scores:

```text
100
90
90
80
```

The results are:

| Score | ROW_NUMBER | RANK | DENSE_RANK |
| ----: | ---------: | ---: | ---------: |
|   100 |          1 |    1 |          1 |
|    90 |          2 |    2 |          2 |
|    90 |          3 |    2 |          2 |
|    80 |          4 |    4 |          3 |

### 4. Using `PARTITION BY`

You can rank **within each group** using `PARTITION BY`.

For example, rank employees by salary **within each department**:

```sql
SELECT
    name,
    department,
    salary,
    RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
```

Each department gets its own ranking starting from `1`.

---

### When to use which?

Use **`RANK()`** when the ranking should reflect competition-style positions:

> Two people tied for 2nd → next person is 4th.

Use **`DENSE_RANK()`** when you want rankings based on distinct values:

> Two people tied for 2nd → next person is 3rd.

For example, if you need the **second-highest distinct salary**, `DENSE_RANK()` is often useful:

```sql
WITH ranked AS (
    SELECT
        name,
        salary,
        DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employees
)
SELECT *
FROM ranked
WHERE rnk = 2;
```

### Interview Takeaway

Remember this simple rule:

> **`RANK()` = same rank + gaps**
> **`DENSE_RANK()` = same rank + no gaps**
> **`ROW_NUMBER()` = every row gets a unique number**

The most important thing is to understand **how ties are handle**
