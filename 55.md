## 55. What is referential integrity?

### Answer

**Referential integrity** is a database rule that ensures relationships between tables remain **valid and consistent**.

In simple terms:

> A **foreign key** in one table should refer to an existing valid key in the related table, unless the foreign key is allowed to be `NULL`.

### Example

Suppose we have two tables:

```text
users
+----+--------+
| id | name   |
+----+--------+
| 1  | Rahul  |
| 2  | Amit   |
+----+--------+

orders
+-----+---------+
| id  | user_id |
+-----+---------+
| 101 | 1       |
| 102 | 2       |
+-----+---------+
```

Here:

```text
orders.user_id → users.id
```

`orders.user_id` is a **foreign key** referencing `users.id`.

Therefore, this is valid:

```sql
INSERT INTO orders (id, user_id)
VALUES (103, 1);
```

because user `1` exists.

But this should fail:

```sql
INSERT INTO orders (id, user_id)
VALUES (104, 999);
```

because user `999` doesn't exist.

This prevents **orphan records**.

---

### How is it enforced?

Using a foreign key constraint:

```sql
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,

    FOREIGN KEY (user_id)
        REFERENCES users(id)
);
```

The database now enforces the relationship rather than relying only on application code.

---

### What about deleting the parent?

Suppose user `1` has orders:

```text
users
  1
  ↓
orders
  101
  102
```

If we try to delete user `1`, the database needs to know what should happen.

Common options are:

#### `RESTRICT`

Prevent deletion while dependent rows exist.

```sql
ON DELETE RESTRICT
```

#### `CASCADE`

Delete related child rows automatically.

```sql
ON DELETE CASCADE
```

#### `SET NULL`

Keep the child row but remove its parent reference.

```sql
ON DELETE SET NULL
```

This requires the foreign-key column to allow `NULL`.

---

### Why is it important?

Without referential integrity, you could have:

```text
users
+----+--------+
| id | name   |
+----+--------+
| 1  | Rahul  |
+----+--------+

orders
+-----+---------+
| id  | user_id |
+-----+---------+
| 101 | 999     |
+-----+---------+
```

The order points to a user that doesn't exist.

That creates inconsistent data and can cause incorrect application behavior.

### Interview Takeaway

> **Referential integrity ensures that relationships between tables remain valid. It is commonly enforced using foreign key constraints, which prevent a child row from referencing a non-existent parent row and can also define what happens when the parent is updated or delete**

## Answer

`NULL` means ?unknown? or ?missing,? not zero or an empty string. It behaves differently from other values in comparisons and aggregates.

```sql
SELECT * FROM users WHERE email IS NULL;
```

### Interview takeaway

Always handle `NULL` carefully with `IS NULL`, `IS NOT NULL`, and `COALESCE` to avoid logic bugs.
