## 30. What are window functions and why are they useful?

### Answer

A **window function** performs a calculation across a set of related rows while **keeping the individual rows in the result**.

This is the key difference from normal aggregate functions.

For example:

* `SUM()` with `GROUP BY` → combines multiple rows into one result per group.
* `SUM() OVER (...)` → calculates across a group of rows but **keeps every original row**.

### Basic Syntax

```sql
function_name(...) OVER (
    PARTITION BY ...
    ORDER BY ...
)
```

The `OVER()` clause defines the **window** of rows that the function should consider.

---

## Simple Example

Suppose we have:

**employees**

| id | name  | department | salary |
| -: | ----- | ---------- | -----: |
|  1 | Sahil | IT         |  50000 |
|  2 | Rahul | IT         |  70000 |
|  3 | Priya | HR         |  60000 |
|  4 | Amit  | HR         |  40000 |

Suppose we want to calculate the **average salary of each department** while still showing every employee.

With a normal `GROUP BY`:

```sql
SELECT department, AVG(salary)
FROM employees
GROUP BY department;
```

Result:

| department | avg_salary |
| ---------- | ---------: |
| IT         |      60000 |
| HR         |      50000 |

The individual employees are no longer present.

With a window function:

```sql
SELECT
    name,
    department,
    salary,
    AVG(salary) OVER (
        PARTITION BY department
    ) AS department_avg
FROM employees;
```

Result:

| name  | department | salary | department_avg |
| ----- | ---------- | -----: | -------------: |
| Sahil | IT         |  50000 |          60000 |
| Rahul | IT         |  70000 |          60000 |
| Priya | HR         |  60000 |          50000 |
| Amit  | HR         |  40000 |          50000 |

The department average is calculated, but **every employee row remains**.

---

## Why are they called "window" functions?

The function operates over a **window of rows** related to the current row.

For example:

```sql
PARTITION BY department
```

creates separate windows:

```text
IT window
┌──────────────────────┐
│ Sahil   50000        │
│ Rahul   70000        │
└──────────────────────┘

HR window
┌──────────────────────┐
│ Priya   60000        │
│ Amit    40000        │
└──────────────────────┘
```

The calculation happens within each window.

---

## `PARTITION BY`

`PARTITION BY` divides the result into groups for the window calculation.

Example:

```sql
AVG(salary) OVER (
    PARTITION BY department
)
```

means:

> Calculate the average salary separately for each department.

Unlike `GROUP BY`, the rows aren't collapsed.

---

## `ORDER BY` inside a window

Window functions can also order rows within each window.

For example, to rank employees by salary within each department:

```sql
SELECT
    name,
    department,
    salary,
    RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
```

Result:

| name  | department | salary | salary_rank |
| ----- | ---------- | -----: | ----------: |
| Rahul | IT         |  70000 |           1 |
| Sahil | IT         |  50000 |           2 |
| Priya | HR         |  60000 |           1 |
| Amit  | HR         |  40000 |           2 |

---

## Common Window Functions

### 1. `ROW_NUMBER()`

Assigns a unique sequential number to each row.

```sql
ROW_NUMBER() OVER (
    PARTITION BY department
    ORDER BY salary DESC
)
```

Useful for:

* Finding the top N records per group
* Deduplicating data
* Selecting the latest record

---

### 2. `RANK()`

Assigns ranks, allowing ties.

```text
Salary
70000 → Rank 1
70000 → Rank 1
50000 → Rank 3
```

There is a gap after the tie.

---

### 3. `DENSE_RANK()`

Also allows ties, but doesn't leave gaps.

```text
Salary
70000 → Rank 1
70000 → Rank 1
50000 → Rank 2
```

### `RANK()` vs `DENSE_RANK()`

```text
RANK:        1, 1, 3
DENSE_RANK:  1, 1, 2
```

This is a common interview question.

---

### 4. `LAG()`

Gets a value from a **previous row**.

For example, compare an employee's salary with the previous salary:

```sql
SELECT
    name,
    salary,
    LAG(salary) OVER (
        ORDER BY salary
    ) AS previous_salary
FROM employees;
```

Useful for:

* Comparing current vs previous month
* Calculating changes
* Time-series analysis

---

### 5. `LEAD()`

Gets a value from a **following row**.

```sql
LEAD(salary) OVER (
    ORDER BY salary
)
```

It is essentially the opposite direction of `LAG()`.

---

### 6. `SUM()`, `AVG()`, `MIN()`, `MAX()`

Aggregate functions can also be used as window functions.

For example, a running total:

```sql
SELECT
    order_date,
    amount,
    SUM(amount) OVER (
        ORDER BY order_date
    ) AS running_total
FROM orders;
```

Result conceptually:

| order_date | amount | running_total |
| ---------- | -----: | ------------: |
| Jan 1      |    100 |           100 |
| Jan 2      |    200 |           300 |
| Jan 3      |    150 |           450 |

The `SUM()` is calculated across the ordered window while each order remains visible.

---

## Window Functions vs GROUP BY

This distinction is extremely important.

### `GROUP BY`

```sql
SELECT department, AVG(salary)
FROM employees
GROUP BY department;
```

Produces:

```text
IT → 60000
HR → 50000
```

Individual employees are collapsed into groups.

### Window Function

```sql
SELECT
    name,
    department,
    salary,
    AVG(salary) OVER (PARTITION BY department)
FROM employees;
```

Produces:

```text
Sahil → IT → 50000 → 60000
Rahul → IT → 70000 → 60000
Priya → HR → 60000 → 50000
Amit  → HR → 40000 → 50000
```

### Mental model

```text
GROUP BY
Rows → Groups → One result per group

Window Function
Rows → Calculate across related rows → Keep original rows
```

---

## Practical Example: Top 2 Employees per Department

This is a very common interview problem.

```sql
WITH ranked_employees AS (
    SELECT
        name,
        department,
        salary,
        ROW_NUMBER() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) AS rn
    FROM employees
)
SELECT
    name,
    department,
    salary
FROM ranked_employees
WHERE rn <= 2;
```

The window function ranks employees **within each department**, and the outer query selects the top two.

---

## Why are window functions useful?

They are especially useful when you need to:

* Rank rows
* Find top N records per group
* Calculate running totals
* Compare current and previous rows
* Calculate percentages or averages while keeping detail rows
* Perform time-series analysis
* Deduplicate records
* Analyze data within groups without collapsing the rows

---

### Interview Takeaway

> **A window function performs a calculation across a related set of rows while preserving the individual rows in the result.**

The most important distinction:

```text
GROUP BY
→ Combines rows into groups

Window Function
→ Calculates across rows but keeps the rows
```

And remember the two most important parts of `OVER()`:

```sql
OVER (
    PARTITION BY ...
    ORDER BY ...
)
```

**`PARTITION BY` → defines which rows belong to the same window.**
**`ORDER BY` → defines the order within that window**

A `UNIQUE` constraint ensures that values in a column are unique across rows. Unlike a primary key, a table can have multiple unique columns.

```sql
CREATE TABLE users (
    id INT PRIMARY KEY,
    email VARCHAR(255) UNIQUE
);
```

### Interview takeaway

Use `UNIQUE` to prevent duplicates while allowing a separate primary key column.
