## 21. What is a CROSS JOIN?

### Answer

A **CROSS JOIN** returns the **Cartesian product** of two tables.

This means **every row from the first table is combined with every row from the second table**.

Unlike `INNER JOIN`, `LEFT JOIN`, or `FULL OUTER JOIN`, a `CROSS JOIN` does **not require a matching condition**.

### Syntax

```sql
SELECT columns
FROM table1
CROSS JOIN table2;
```

### Example

Suppose we have:

**sizes**

| id | size   |
| -: | ------ |
|  1 | Small  |
|  2 | Medium |
|  3 | Large  |

**colors**

| id | color |
| -: | ----- |
|  1 | Red   |
|  2 | Blue  |

```sql
SELECT
    s.size,
    c.color
FROM sizes s
CROSS JOIN colors c;
```

Result:

| size   | color |
| ------ | ----- |
| Small  | Red   |
| Small  | Blue  |
| Medium | Red   |
| Medium | Blue  |
| Large  | Red   |
| Large  | Blue  |

Every size is paired with every color.

### How many rows are produced?

If:

* Table A has **M rows**
* Table B has **N rows**

Then:

```text
Result rows = M × N
```

For the example:

```text
3 sizes × 2 colors = 6 rows
```

If one table has 1,000 rows and another has 1,000 rows:

```text
1,000 × 1,000 = 1,000,000 rows
```

So a CROSS JOIN can produce a **very large result set**.

### CROSS JOIN vs INNER JOIN

**INNER JOIN:**

```sql
SELECT *
FROM users u
INNER JOIN orders o
    ON u.id = o.user_id;
```

Only related/matching rows are returned.

**CROSS JOIN:**

```sql
SELECT *
FROM users u
CROSS JOIN orders o;
```

Every user is paired with every order, regardless of whether they are related.

### Practical use

CROSS JOIN is useful when you intentionally need **all possible combinations**.

For example:

* Generate every **product × color** combination
* Generate every **employee × shift** combination
* Generate every **date × store** combination for reporting
* Generate possible configuration combinations

### Common Mistake

Do not use `CROSS JOIN` accidentally when you intended to join related records.

For example, forgetting a join condition in some older-style SQL syntax can unintentionally create a Cartesian product and produce **far more rows than expected**.

### Interview Takeaway

> **CROSS JOIN produces the Cartesian product of two tables, meaning every row from the first table is combined with every row from the second table.**

Remember:

**CROSS JOIN = all possible combination**

## Answer

A subquery is a query nested inside another query. It can appear in `SELECT`, `FROM`, `WHERE`, or `HAVING` clauses.

```sql
SELECT *
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```

### Interview takeaway

Subqueries are useful for decomposing logic, but they can sometimes be less efficient than joins for large data sets.
