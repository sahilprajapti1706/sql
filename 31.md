## 31. What is the difference between GROUP BY and window functions?

### Answer

The main difference is:

> **`GROUP BY` combines rows into groups and returns one row per group, while a window function performs calculations across related rows but keeps the individual rows in the result.**

This is one of the most important SQL concepts to understand.

---

## 1. GROUP BY

`GROUP BY` divides rows into groups and usually performs an **aggregate calculation** for each group.

Suppose we have:

| name  | department | salary |
| ----- | ---------- | -----: |
| Sahil | IT         |  50000 |
| Rahul | IT         |  70000 |
| Priya | HR         |  60000 |
| Amit  | HR         |  40000 |

To calculate the average salary per department:

```sql
SELECT
    department,
    AVG(salary) AS avg_salary
FROM employees
GROUP BY department;
```

Result:

| department | avg_salary |
| ---------- | ---------: |
| IT         |      60000 |
| HR         |      50000 |

Notice that the individual employee rows are **collapsed**.

---

## 2. Window Function

A window function can calculate the same average while **keeping every employee row**.

```sql
SELECT
    name,
    department,
    salary,
    AVG(salary) OVER (
        PARTITION BY department
    ) AS avg_department_salary
FROM employees;
```

Result:

| name  | department | salary | avg_department_salary |
| ----- | ---------- | -----: | --------------------: |
| Sahil | IT         |  50000 |                 60000 |
| Rahul | IT         |  70000 |                 60000 |
| Priya | HR         |  60000 |                 50000 |
| Amit  | HR         |  40000 |                 50000 |

The average is calculated for each department, but the employee details remain available.

---

## Key Difference

| `GROUP BY`                   | Window Function                                         |
| ------------------------------ | ------------------------------------------------------- |
| Groups rows                    | Defines a window of rows                                |
| Usually reduces number of rows | Keeps original number of rows                           |
| Produces one result per group  | Produces a result for each row                          |
| Commonly used with aggregates  | Can use aggregates, ranking,`LAG()`, `LEAD()`, etc. |
| Good for summaries             | Good for analysis while retaining detail                |

---

## A simple mental model

### GROUP BY

```text
Employee rows
      ↓
   GROUP BY
      ↓
Department groups
      ↓
One result per department
```

```text
IT  → 60000
HR  → 50000
```

### Window Function

```text
Employee rows
      ↓
Window calculation
      ↓
Same employee rows + calculated value
```

```text
Sahil → IT → 50000 → 60000
Rahul → IT → 70000 → 60000
Priya → HR → 60000 → 50000
Amit  → HR → 40000 → 50000
```

---

## Example: Ranking

This is something `GROUP BY` cannot naturally do.

Suppose we want to rank employees by salary within each department:

```sql
SELECT
    name,
    department,
    salary,
    RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
```

Result:

| name  | department | salary | salary_rank |
| ----- | ---------- | -----: | ----------: |
| Rahul | IT         |  70000 |           1 |
| Sahil | IT         |  50000 |           2 |
| Priya | HR         |  60000 |           1 |
| Amit  | HR         |  40000 |           2 |

The original employee rows are preserved.

---

## Another important difference: comparing rows

Window functions can compare one row with another using functions such as:

```sql
LAG()
LEAD()
```

Example:

```sql
SELECT
    order_date,
    amount,
    LAG(amount) OVER (
        ORDER BY order_date
    ) AS previous_amount
FROM orders;
```

This is useful for things like:

* Current month vs previous month
* Current order vs previous order
* Growth calculations
* Time-series analysis

`GROUP BY` is not designed for this kind of row-to-row analysis.

---

## Can GROUP BY and window functions be used together?

**Yes.**

For example:

```sql
SELECT
    department,
    COUNT(*) AS employee_count,
    RANK() OVER (
        ORDER BY COUNT(*) DESC
    ) AS department_rank
FROM employees
GROUP BY department;
```

Here:

1. `GROUP BY` creates one row per department.
2. `COUNT(*)` calculates employees per department.
3. The window function ranks those department-level results.

So they are not competing features—they can be used together.

---

## When should you use which?

### Use `GROUP BY` when:

You want a **summary**.

Examples:

> "How many employees are in each department?"

```sql
GROUP BY department
```

> "What is the total sales for each customer?"

```sql
GROUP BY customer_id
```

### Use window functions when:

You need a calculation **while keeping the individual rows**.

Examples:

> "Show each employee and their department's average salary."

```sql
AVG(salary) OVER (PARTITION BY department)
```

> "Rank employees within each department."

```sql
RANK() OVER (PARTITION BY department ORDER BY salary DESC)
```

> "Show the previous order amount."

```sql
LAG(amount) OVER (ORDER BY order_date)
```

---

### Interview Takeaway

> **`GROUP BY` reduces rows by grouping them, while window functions perform calculations across related rows without collapsing the original rows.**

The easiest way to remember:

```text
GROUP BY
→ "Summarize these rows."

Window Function
→ "Analyze these rows, but keep them."
```

If the question says **"give me one result per group"**, think `GROUP BY`.

If it says **"show every row along with some group/ranking/comparison information"**, think **window functio**
