## 19. Explain RIGHT JOIN

### Answer

A **`RIGHT JOIN`** returns:

1. **All rows from the right table**, and
2. Matching rows from the left table.

If there is no matching row in the left table, the left-table columns contain `NULL`.

> **RIGHT JOIN = Keep everything from the right table, and add matching data from the left table.**

---

## Example

Suppose we have:

### `users`

| id | name  |
| -: | ----- |
|  1 | Sahil |
|  2 | Rahul |
|  3 | Priya |

### `orders`

|  id | user_id | amount |
| --: | ------: | -----: |
| 101 |       1 |    500 |
| 102 |       2 |    800 |
| 103 |       1 |   1200 |
| 104 |       5 |    300 |

Now:

```sql
SELECT
    u.name,
    o.id AS order_id,
    o.amount
FROM users AS u
RIGHT JOIN orders AS o
    ON u.id = o.user_id;
```

### Result

| name  | order_id | amount |
| ----- | -------: | -----: |
| Sahil |      101 |    500 |
| Rahul |      102 |    800 |
| Sahil |      103 |   1200 |
| NULL  |      104 |    300 |

Notice:

* Orders `101`, `102`, and `103` have matching users.
* Order `104` has `user_id = 5`, but there is no user with `id = 5`.
* Because `orders` is the **right table**, order `104` is still included.
* The missing user's columns become `NULL`.

---

# How RIGHT JOIN Works

Think of:

```sql
FROM users AS u
RIGHT JOIN orders AS o
    ON u.id = o.user_id
```

as:

```text
LEFT TABLE                 RIGHT TABLE

users                      orders

1  Sahil  ──────────────→  1  500
2  Rahul  ──────────────→  2  800
3  Priya                   1  1200
                            5  300
                            ↑
                       No matching user
```

Since `orders` is on the **right**, every order is preserved.

For an order without a matching user:

```text
u.id       → NULL
u.name     → NULL
o.id       → 104
o.amount   → 300
```

---

# RIGHT JOIN vs LEFT JOIN

They are essentially mirror images.

### LEFT JOIN

```sql
SELECT *
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id;
```

Keeps **all users**.

### RIGHT JOIN

```sql
SELECT *
FROM users u
RIGHT JOIN orders o
    ON u.id = o.user_id;
```

Keeps **all orders**.

|                              | LEFT JOIN                       | RIGHT JOIN                     |
| ---------------------------- | ------------------------------- | ------------------------------ |
| Preserves all rows from      | Left table                      | Right table                    |
| Unmatched other-side columns | `NULL`                        | `NULL`                       |
| Example                      | All users + orders if available | All orders + user if available |

---

# RIGHT JOIN Can Be Rewritten as LEFT JOIN

Anything you can do with a `RIGHT JOIN` can generally be expressed using a `LEFT JOIN` by swapping the table order.

For example:

```sql
SELECT *
FROM users u
RIGHT JOIN orders o
    ON u.id = o.user_id;
```

is equivalent in result to:

```sql
SELECT *
FROM orders o
LEFT JOIN users u
    ON u.id = o.user_id;
```

This is why many developers prefer `LEFT JOIN`: keeping the "important" or preserved table on the left can make complex queries easier to read.

---

# When Would You Use RIGHT JOIN?

A `RIGHT JOIN` is useful when the **right-hand table is the table whose every row must be preserved**.

For example:

> "Show every order, including orders whose user record is missing."

```sql
SELECT
    o.id,
    o.amount,
    u.name
FROM users u
RIGHT JOIN orders o
    ON u.id = o.user_id;
```

However, in practice, you can usually write the same query more naturally as:

```sql
SELECT
    o.id,
    o.amount,
    u.name
FROM orders o
LEFT JOIN users u
    ON o.user_id = u.id;
```

---

## Important Point

The table's **position** determines which rows are preserved.

```sql
FROM A
LEFT JOIN B
```

→ All rows from **A**

```sql
FROM A
RIGHT JOIN B
```

→ All rows from **B**

Don't confuse this with the direction of the relationship between the tables.

---

## Interview Takeaway

> **RIGHT JOIN returns all rows from the right table and matching rows from the left table. If a right-table row has no match, the left-table columns contain `NULL`.**

Remember:

```text
LEFT JOIN
→ Keep everything on the LEFT

RIGHT JOIN
→ Keep everything on the RIGHT
```

And a useful practical point:

> **A `RIGHT JOIN` can usually be rewritten as a `LEFT JOIN` by swapping the table order, which is why `LEFT JOIN` is more commonly seen in application cod**

## Answer

A self join is a join where a table is joined to itself. It is used when a table contains hierarchical or related rows that need to be compared.

```sql
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m
  ON e.manager_id = m.id;
```

### Interview takeaway

Self joins are common in employee, category, and hierarchy-based datasets.
